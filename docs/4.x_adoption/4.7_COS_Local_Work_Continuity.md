# 4.7 — Local Work Continuity
## Version: 0.1.0
Last Updated: 2026-09-08
Owner: Context OS Maintainers
Status: local candidate; assisted user trial pending

## Start with the work

**Reusable instruction to Codex:** “Retomemos este frente con Context OS usando
su carpeta de continuidad.” Include the saved folder once when opening a new
conversation; it is the explicit handoff, not private chat memory. This is an
instruction to a consumer, not a Runtime natural-language command.

The consumer runs one [local composition script](../../tools/continuity/continue_work.py)
for first orientation and return. It shows sourced purpose, state, existing
work, next decision/condition, value links, governing decisions and unknowns.
The result prepares a continuation; it never executes target work. Context OS
remains an Organizational Context Runtime, Design-Partner Alpha.

| Actor | Responsibility and limitation |
|---|---|
| Context OS | Copy only permitted documentary sources; check profile, source identities, Activation, Context Version and supplied Work Ownership; persist derived evidence; detect material changes; render operator-prepared statements with matching citations |
| Codex / technical operator | Resolve the intended front and authorized source scope; prepare the saved input; read/interpret sources; compare proposals with governing decisions; distinguish supported statements from hypotheses; inspect blocked checks; record all assistance |
| Person with the relevant authority | Clarify material intent/ownership, verify architectural exceptions and accept or reject the proposed continuation; approve future consequential actions separately |

Citation matching proves that text occurs in a permitted source. It does not
prove the operator's paraphrase, semantic fit, source completeness, current
production behavior, approver authenticity or business value. A source can
have been read without its restrictions being checked. Candidate-authored
documentation and green tests are not product acceptance.

## Try the synthetic route

Run from a Context OS checkout on macOS with Python 3.9+ and Git. Use a new
stable directory outside both Context OS and the target. No package install
is required. The sample is **synthetic**, not organization creation or an
external profile approval. These setup commands are for the operator; the
end user should not assemble JSON or repeat a command chain.

```bash
python3 tools/continuity/synthetic_example.py "$HOME/contextos-continuity-demo"
python3 tools/continuity/continue_work.py "$HOME/contextos-continuity-demo/work"
```

Exit the process. Run the second command again, including from a different
conversation. The saved anchor and freshly read corpus supply continuity.
For machine evidence, use the same command with `--format json`. Standard
output is one JSON value, including failures. Exit 0 means a brief is prepared
for review; exit 2 means clarification, re-anchor or recovery is needed. Neither
exit means a proposal is authorized to implement.

## Prepare an existing front once

Codex/the operator uses the public [synthetic input builder](../../tools/continuity/synthetic_example.py)
as the complete input example, replacing its synthetic declarations with
authorized evidence. Save `work.json` in a private continuity folder, never
the target or Context OS repository. This preparation is assisted adoption;
measure mapping time, source reads, procedural help and maintainer time.

1. Establish repository-bound authority and the bounded front. Use an approved
   Adoption Profile for an external target. Native authorized corpora can omit
   the profile. Missing approved mappings stay unknown; do not copy the sample's
   synthetic approval or infer ownership from native fallback.
2. Set `target_id`, `intent`, `profile` (absolute path when used), and `source`.
   Use `local_corpus` with an authorized documentary directory, or
   `published_git_docs` with the **registered** `root`, `repository`, repository-bound
   `identity`, and explicit `visible_sources` under docs/. The published reader
   runs preflight on each return, resolves live origin/main and reads only
   regular documentary blobs at that SHA. It never fetches, checks out or writes
   to the target. If the live object is absent locally, stop and resolve corpus
   access separately. An unregistered clone is not an authority workaround.
3. List excluded paths in `withheld_sources`. They cannot overlap the read
   allowlist. Only copied, permitted documents enter the engines. No code,
   credentials, customer data or provider surfaces belong in this corpus.
   A local corpus is reported as local, never as published truth. Its source
   authority must have been established by the operator beforehand.
4. Prepare `claims`: objective, audience, state, existing_work, next, value,
   indicator. Each optional field has short `text` and `citations` containing
   a source `path` and exact `quote`. The operator is responsible for the
   text-to-quote relationship. Omit unsupported claims; identify candidate
   indicators and unknown baselines explicitly. Put hypotheses in
   `interpretations`, never in sourced claims.
5. Save relevant `governing_decisions` with text, citations, `checked_by` and
   `check_scope`. Omit the reviewer if only read. For a proposal, supply `review`
   with proposal text, constraint_refs, reviewed_by and an interpreted `fit`:
   compatible, conflict or unknown. An approved_exception additionally needs
   decision_refs, human_approver, authority_verified_by and an explicit
   independent_of_candidate declaration. These are attributed review inputs,
   not Runtime verification of authority. Review the exact accepted exception
   and its scope; a candidate's own document change is insufficient.
6. Supply `ownership` only with the existing Work Ownership API's need, work
   items, source declarations and coverage. Existing target mappings and
   lifecycle semantics must support it. Otherwise report unknown while still
   showing documentary references to existing work. No automatic new work is
   created, even when the resolver allows ordinary qualification.

This route deliberately does not retrieve organizational memory without its
policy workflow. “Not retrieved” does not mean no prior work exists. It does
not synthesize Mission-use evidence from opening a file or running tests.
Health and Mission-use remain available for actual use evidence, but adding
their reports would not remove this slice's initial continuity friction.

## Return, re-anchor and recover

Run the same command. A changed visible source, profile, input interpretation,
visibility boundary or invalid saved Activation requires re-anchor. Changes to
unread files or an unrelated Git tip alone do not. File-level comparison is
conservative: it does not semantically classify edits within a selected file.
Published Git acquisition time is reported separately from Runtime composition.

After the operator reviews changed sources, restrictions and interpretations,
updates the input if necessary, and records any separate human decision:

```bash
python3 tools/continuity/continue_work.py "$HOME/contextos-continuity-demo/work" --reanchor --reason "Reviewed the changed sources and governing constraints"
```

Re-anchor is an operator checkpoint, not approval to implement a proposal.
Missing/altered local anchor evidence fails explicitly. Restore authentic
evidence from a trusted backup or begin a new reference, acknowledging the gap:

```bash
python3 tools/continuity/continue_work.py "$HOME/contextos-continuity-demo/work" --recover --reason "Local evidence lost; prior history unknown"
```

Derived files are ordinary local files using existing stable hashes and
Runtime artifact identities: `runs/<id>/corpus/`, `record.json` (package,
handoff, capture plan/version when possible, checks, interpretation and timings),
`anchor.json` and `last.json` (atomic hash-bound pointers). The folder is private
to its local OS user. Files have mode 0600; the enclosing folder has mode 0700.
They are not a new canon, database, approval mechanism or background service.
Use the whole folder for backup; no automatic deletion/retention is implemented.
Do not share JSON details containing private excerpts. Losing the entire folder
cannot be distinguished from a first run; report no prior reference and do not
invent history. The script cannot restore missing human decisions.

If the approved profile requires documents outside the allowed corpus, the
capture can remain blocked. The sourced brief may still aid orientation, but
its limits remain visible; do not expand access or modify the approved profile
just to turn the result green. Missing objective/state/next information asks
for material clarification. Unknown indicators do not authorize measurement
or require inventing a business metric. “Creating an organization” remains a
future entry: use the incomplete-context case, not a generated company.

## Human trial prepared, not performed

Before recruiting, agree the permitted corpus, answer key and material
decision boundaries with its owner. Record the key independently of the
generated brief. Compare the existing manual document-reading workflow with
this assisted route on matched work, counterbalancing order where possible.
Record familiarity with known cases, including the founder's strong bias.
There is no historical baseline or measured improvement yet.

| Episode | Task | Proposed threshold, to agree before measuring |
|---|---|---|
| First orientation | Correctly explain objective, current state, existing work, integration boundary and next decision | Within 5 minutes; no critical authority/architecture error; at most one substantive correction |
| Return | Resume from saved folder in another process | Within 2 minutes; no manual reconstruction of the original brief; no critical error |
| Material change | Identify a changed constraint and require re-anchor | Within 5 minutes; no stale continuation presented as authorized; no critical error |

Propose at most 10 minutes of procedural setup help and 1 minute of help on
return as research thresholds; failures count, including maintainer preparation.
Each episode also needs explicit brief acceptance as sufficient to decide how
to continue. Report raw measurements, not percentages from nonexistent history.
Use a controlled changed corpus for episode 3; these episodes grant no target
mutation authority.

For each episode record: correct-understanding start/end, answer-key assessment,
substantive corrections and severity, brief acceptance/reason, procedural help
and maintainer minutes, Codex work minutes, extra source reads/time, waiting,
and strategic/authority intervention separately. The script measures acquisition
and Runtime durations only; its human_measurements remains null. Technical
tests, an isolated demonstration, integrated continuation and human product
acceptance are different evidence classes.

Prepare the later Gate 2 trial with two technical operators unfamiliar with
Runtime internals, one authorized native corpus and one existing-canon corpus.
Give them this guide; record all rescue and false blockers. No operators have
been contacted or counted. Founder-assisted research does not pass that gate,
nor do tests or a role-played agent. This route does not claim repeated operation,
independent adoption, cognitive savings or business value.
