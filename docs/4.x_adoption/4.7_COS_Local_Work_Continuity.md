**Reusable instruction to Codex:** “Retomemos este frente con Context OS usando
su carpeta de continuidad.” Include the saved folder once when opening a new
conversation; it is the explicit handoff, not private chat memory. This is an
instruction to a consumer, not a Runtime natural-language command.

The consumer runs one [local composition script](../../tools/continuity/continue_work.py)
for first orientation and return. It shows sourced purpose, state, existing
work, next decision/condition, value links, governing decisions and unknowns.
The result prepares a continuation; it never executes target work. Context OS
remains an Organizational Context Runtime, Design-Partner Alpha.

| Actor | Responsibility and limitation |
|---|---|
| Context OS | Copy only permitted documentary sources; check profile, source identities, Activation, Context Version and supplied Work Ownership; persist derived evidence; detect material changes; render operator-prepared statements with matching citations |
| Codex / technical operator | Resolve the intended front and authorized source scope; prepare the saved input; read/interpret sources; compare proposals with governing decisions; distinguish supported statements from hypotheses; inspect blocked checks; record all assistance |
| Person with the relevant authority | Clarify material intent/ownership, verify architectural exceptions and accept or reject the proposed continuation; approve future consequential actions separately |

Citation matching proves that text occurs in a permitted source. It does not
prove the operator's paraphrase, semantic fit, source completeness, current
production behavior, approver authenticity or business value. A source can
have been read without its restrictions being checked. Candidate-authored
documentation and green tests are not product acceptance.

## Try the synthetic route

Run from a Context OS checkout on macOS with Python 3.9+ and Git. Use a new
stable directory outside both Context OS and the target. No package install
is required. The sample is **synthetic**, not organization creation or an
external profile approval. These setup commands are for the operator; the
end user should not assemble JSON or repeat a command chain.

```bash
python3 tools/continuity/synthetic_example.py "$HOME/contextos-continuity-demo"
python3 tools/continuity/continue_work.py "$HOME/contextos-continuity-demo/work" --format json
```

That output is for the operator. After preparing and checking Spanish reader
wording as described below, run the same command without `--format json` for
the person's first reading. A later invocation uses the saved folder and freshly
read corpus; it does not reconstruct the work from chat memory. The original
technical human rendering remains available with `--format detail`; machine
evidence remains `--format json`, including failures. The existing exit codes
still describe the underlying record (0 prepared for review, 2 limited/blocked),
not human comprehension or the quality of its wording. Neither authorizes execution.

## A first reading that explains the work

The reusable [reader renderer](../../tools/continuity/reader_brief.py) presents
case, existing work, goal and beneficiaries before the proposal. It separately
names who must review or decide, without assigning that role to the reader.
It exposes missing proposal detail, material restrictions and unknowns, selects
one continuation from the original control results, and keeps preparation
distinct from approval and implementation. A favorable interpretation does not
become acceptance. The synthetic case and unproven benefit remain explicit.

Codex/the operator writes `brief.es.json` in the private continuity folder after
reading the checked record and its permitted sources. The person using the
product is not asked to assemble this file, hashes or Runtime commands. This
assisted wording is translation and interpretation by Codex/the operator;
Runtime does not generate, understand or certify its Spanish semantics.

The local wording contains `language: es`, `authored_by`, `case_kind` (synthetic,
documentary or unknown), `case`, `work`, `objective`, `beneficiaries` and, when
known, `decision_owner` and `proposal`. `proposal_detail` is described or
insufficient; an insufficient proposal includes `proposal_missing` and a
`clarification_question` based on the information actually absent. Do not invent
design detail to fill these fields. Only describe a responsible actor when
supported by current evidence; no reader role is assumed.

The wording's `binding` is produced by `wording_binding(record)`. Every current
`governing_decisions` item and every `gaps` item must have a respective entry in
`restrictions` or `unknowns`, with its existing stable hash as `binding` and
faithful Spanish `text`. This checks exact coverage, not meaning. A separate
fidelity review must compare the actual wording with the original sources,
including provenance, authority limits and missing information. Changing wording
does not change the machine record, source, profile, oracle, approval or sufficiency.

The binding excludes display clocks and per-run artifact identifiers; unchanged
facts and controls can retain their wording on return. A material change makes
the old wording unusable until the operator checks and updates it. Missing,
malformed, stale or incomplete wording produces a Spanish clarification notice,
not foreign source text or an apparently reviewed proposal. Privacy-limited
records use a generic safe notice, never cached wording that may contain revoked
information. Permitted details and all original control evidence remain in the
technical view. These presentation limits do not alter the Runtime's gates.

For a presentation-only iteration, the operator can call `render_reader(record,
wording)` on the preserved checked record and save that output, clearly marking
it as a redescription of that observation rather than a fresh source check.
Capture the original brief, exact human response, any assistance and every later
presentation separately. Do not restart the first-reading measurement, infer
attention from message intervals or treat technical tests as understanding.

## Prepare an existing front once

Codex/the operator uses the public [synthetic input builder](../../tools/continuity/synthetic_example.py)
as the complete input example, replacing its synthetic declarations with
authorized evidence. Save `work.json` in a private continuity folder, never
the target or Context OS repository. This preparation is assisted adoption;
measure mapping time, source reads, procedural help and maintainer time.

1. Establish repository-bound authority and the bounded front. Use an approved
   Adoption Profile for an external target. Native authorized corpora can omit
   the profile. Missing approved mappings stay unknown; do not copy the sample's
   synthetic approval or infer ownership from native fallback.
2. Set `target_id`, `intent`, `profile` (absolute path when used), and `source`.
   Use `local_corpus` with an authorized documentary directory, or
   `published_git_docs` with the **registered** `root`, `repository`, repository-bound
   `identity`, and explicit `visible_sources` under docs/. The published reader
   runs preflight on each return, resolves live origin/main and reads only
   regular documentary blobs at that SHA. It never fetches, checks out or writes
   to the target. If the live object is absent locally, stop and resolve corpus
   access separately. An unregistered clone is not an authority workaround.
3. List excluded paths in `withheld_sources`. They cannot overlap the read
   allowlist. Only copied, permitted documents enter the engines. No code,
   credentials, customer data or provider surfaces belong in this corpus.
   A local corpus is reported as local, never as published truth. Its source
   authority must have been established by the operator beforehand.
4. Prepare `claims`: objective, audience, state, existing_work, next, value,
   indicator. Each optional field has short `text` and `citations` containing
   a source `path` and exact `quote`. The operator is responsible for the
   text-to-quote relationship. Omit unsupported claims; identify candidate
   indicators and unknown baselines explicitly. Put hypotheses in
   `interpretations`, never in sourced claims.
5. Save relevant `governing_decisions` with stable id, text, citations, `checked_by` and
   `check_scope`. Include the reviewed `source_hash` with each citation; omit
   the reviewer if only read. Invalid quotes, missing/changed sources and known
   restrictions removed from an existing anchor remain visible as unverifiable.
   Protected references retain only a generic existence notice. Dependent
   proposals require clarification; safe partial orientation can remain useful.
   See the exact proposal/review procedure below.
6. Supply `ownership` only with the existing Work Ownership API's need, work
   items, source declarations and coverage. Existing target mappings and
   lifecycle semantics must support it. Otherwise report unknown while still
   showing documentary references to existing work. No automatic new work is
   created, even when the resolver allows ordinary qualification.

This route deliberately does not retrieve organizational memory without its
policy workflow. “Not retrieved” does not mean no prior work exists. It does
not synthesize Mission-use evidence from opening a file or running tests.
Health and Mission-use remain available for actual use evidence, but adding
their reports would not remove this slice's initial continuity friction.

## Exact proposal, review and documentary exception

Keep `proposal` (id, version, content, author and scope) separate from `review`
(fit, reviewed_by, rationale, constraint_refs and optional authority_refs /
decision_refs). After actually comparing the exact proposal with its governing
context, the operator records `review.binding` using `review_binding` in the
[presentation checks](../../tools/continuity/review_evidence.py). The public
synthetic builder shows the complete call. It binds proposal bytes, version,
scope, governing declarations, source hashes, profile and attributed judgement.
The ordinary return command never computes a replacement acceptance binding.
Restriction identity is separate from its reviewed content: retain its id when
updating evidence, and record the new judgement. Removing a known id preserves
an uncertainty notice. For an older input without ids, add an id while retaining
its text, review and re-anchor that migration before changing its meaning.
Updating one after an actual new review is measurable operator assistance;
the end user supplies intent and material decisions, not hashes or JSON.

An exception requires separate documentary authority and decision references.
The local packaging uses exact JSON quotations of existing authority/decision
evidence; it adds no Runtime schema or authentication service. Where prose is
the canon, an authorized actor must first supply/check its structured rendition.
The consumer cannot create approval by transcribing its own proposal. Missing
structured evidence remains unknown, even when a human could interpret the prose.
An external profile must already recognize the authority source as current
canonical governance/authority evidence; this route cannot approve that mapping.

Authority evidence identifies actor, actor_kind, role, capability
(`architecture_exception`), scope, valid_from and valid_until, and an explicit
allow_self_approval when applicable. Decision evidence separately records
human_owner, outcome (`accepted`), the exact proposal_hash and
governing_context_hash, scope and its validity interval. Use the existing
[human authority model](../3.x_operation/3.6_COS_Human_Agent_Authority_Model.md)
and the target's actual policy to substantiate these declarations. A founder
may propose and approve where that policy permits; an agent's self-assigned
human role or a citation of the norm being excepted is insufficient. The local
adapter conservatively requires a separate decision document. Co-located or
pure-prose decisions require clarification, not invented permission.

The result reports documentary corroboration and exact bindings, with actor,
scope and dates visible. It does **not** authenticate authorship or certify that
a selected authority source is genuine. Distinct declared names do not prove
independence; the same declared author/reviewer is shown as self-review and
cannot claim independent review. Human/Codex judgement still detects the
architectural conflict. Every ordinary return checks decision validity against
the current clock, and context/decision changes invalidate reuse. Synthetic
exception records authorize nothing outside their fixture.

## Return, re-anchor and recover

Run the same command. A changed visible source, profile, input interpretation,
visibility boundary or invalid saved Activation requires re-anchor. Changes to
unread files or an unrelated Git tip alone do not. File-level comparison is
conservative: it does not semantically classify edits within a selected file.
Published Git acquisition time is reported separately from Runtime composition.

After the operator reviews changed sources, restrictions and interpretations,
updates the input if necessary, and records any separate human decision:

```bash
python3 tools/continuity/continue_work.py "$HOME/contextos-continuity-demo/work" --reanchor --reason "Reviewed the changed sources and governing constraints"
```

Re-anchor is an operator checkpoint, not approval to implement a proposal.
It cannot repair an invalid proposal review binding or an expired decision.
Visibility withdrawal suppresses Runtime detail that might contain protected
profile/history metadata, leaving a limited brief. Historical files remain
private; the script does not read revoked historical source contents or delete
evidence. Only explicitly marked references can be classified this way; the
operator must exclude protected data from otherwise unmarked free text.
The partial brief is saved as the last orientation; it never replaces a usable
anchor. Repeated restricted returns remain partial without accumulating gaps.
When visibility returns, the preserved anchor and exact review can be checked
again. A folder born partial has no verified anchor: recovery acknowledges
unknown prior context and cannot erase a known restriction or grant sufficiency.
An anonymous protected restriction that was never verifiable needs actual
evidence reconciliation; a reset or a fresh label cannot establish its meaning.
Missing/altered local anchor evidence fails explicitly. Restore authentic
evidence from a trusted backup or begin a new reference, acknowledging the gap:

```bash
python3 tools/continuity/continue_work.py "$HOME/contextos-continuity-demo/work" --recover --reason "Local evidence lost; prior history unknown"
```

Derived files are ordinary local files using existing stable hashes and
Runtime artifact identities: `runs/<id>/corpus/`, `record.json` (package,
handoff, capture plan/version when possible, checks, interpretation and timings),
`anchor.json` and `last.json` (atomic hash-bound pointers). The folder is private
to its local OS user. Files have mode 0600; the enclosing folder has mode 0700.
They are not a new canon, database, approval mechanism or background service.
Use the whole folder for backup; no automatic deletion/retention is implemented.
Do not share JSON details containing private excerpts. Losing the entire folder
cannot be distinguished from a first run; report no prior reference and do not
invent history. The script cannot restore missing human decisions.

If the approved profile requires documents outside the allowed corpus, the
capture can remain blocked. The sourced brief may still aid orientation, but
its limits remain visible; do not expand access or modify the approved profile
just to turn the result green. Missing objective/state/next information asks
for material clarification. Unknown indicators do not authorize measurement
or require inventing a business metric. “Creating an organization” remains a
future entry: use the incomplete-context case, not a generated company.

## Later observations and bounded dispositions

The return reads both the accepted anchor and the hash-checked last orientation.
Permitted observations are folded into the next existing record, so an older
anchor cannot erase a later known restriction. A missing observation remains
pending: machine status, human brief and proposal eligibility are limited
together. It does not become canon or authority through recency. Pending
restrictions do not replace the accepted anchor, even with `--reanchor`.

Reintroducing an observation needs a fresh exact review. A separate, currently
valid documentary human decision may instead confirm, reject, supersede or
declare it not applicable. The decision quotes `observation_dispositions` with
the exact `observation_hash`, disposition and rationale; supersession also names
a current replacement. The review's `observation_refs` bind its permitted source
quotations. These are optional fields in local derived evidence, not a new
Runtime schema or an authority grant. Codex prepares this evidence after actual
review; a person need not construct hashes. Documentary authenticity and semantic
applicability still require human/Codex interpretation. Resolutions remain in
history and are checked again on each return; absent or expired decisions limit
reuse again.

A terminal disposition (`rejected`, `not_applicable`, `superseded`) can settle
the exact recorded historical observation even after the current source removes
its quote. Its old citation remains marked unverifiable; the separate current
decision and authority support the disposition, not the truth of the old quote.
Confirmation still requires current citation support. The original references
must remain explicitly covered by the review, visible under today's policy,
and bound to the exact observation hash. Missing local history is not repaired
by a disposition label.

Reusing an identifier is not a disposition. The adapter accepts literal
preservation of the prior text and path/quotation set (including additive
clarification or refreshed source hashes under exact review). A non-preserving
revision stays alongside the prior observation until a bounded disposition.
This checks literal coverage only; it does not infer semantic equivalence.

Folders are now bound to the exact target, profile, work intention and proposal
scope. A change requires a separate folder; `--reanchor` cannot mix those scopes.
Legacy records must prove the same scope from their existing proposal and
provenance; missing scope evidence fails safely. Missing or altered
last-record evidence fails; explicit recovery preserves unknown history and
cannot declare sufficiency. Restore trusted evidence to resolve that gap.
Local eligibility markers distinguish a deliberately unanchored limited record
from a missing usable anchor. Ordinary partial returns need no fictional recovery.

Visibility is checked anew. Protected observations become one generic notice,
without their text, identity, source hash or cardinality. A notice covered exactly
by the preserved anchor can be rechecked when that visibility returns. Unknown
protected origins remain limited; this slice does not reconcile their identities.

This limitation also applies when a visible observation was saved only in a
partial orientation and later became redacted before entering the accepted
anchor. Returning visibility alone does not reconcile its anonymous notice,
even if the operator reintroduces the same rule. That scenario remains limited
and pending; it is not only a limitation of folders born with protected evidence.

## Human trial: first reading failed; later episodes stopped

The founder's actual first response reported no understanding. That result is
retained; a later ChatGPT explanation was reported as assistance, with its exact
text unavailable in this record. The next presentation corrects the same case
with assistance. Episodes 2 and 3 will not continue under this attempt. The
protocol below remains the original research design, not a claim that its
episodes were completed or its thresholds passed.

Before recruiting, agree the permitted corpus, answer key and material
decision boundaries with its owner. Record the key independently of the
generated brief. Compare the existing manual document-reading workflow with
this assisted route on matched work, counterbalancing order where possible.
Record familiarity with known cases, including the founder's strong bias.
There is no historical baseline or measured improvement yet.

| Episode | Task | Proposed threshold, to agree before measuring |
|---|---|---|
| First orientation | Correctly explain objective, current state, existing work, integration boundary and next decision | Within 5 minutes; no critical authority/architecture error; at most one substantive correction |
| Return | Resume from saved folder in another process | Within 2 minutes; no manual reconstruction of the original brief; no critical error |
| Material change | Identify a changed constraint and require re-anchor | Within 5 minutes; no stale continuation presented as authorized; no critical error |

Propose at most 10 minutes of procedural setup help and 1 minute of help on
return as research thresholds; failures count, including maintainer preparation.
Each episode also needs explicit brief acceptance as sufficient to decide how
to continue. Report raw measurements, not percentages from nonexistent history.
Use a controlled changed corpus for episode 3; these episodes grant no target
mutation authority.

For each episode record: correct-understanding start/end, answer-key assessment,
substantive corrections and severity, brief acceptance/reason, procedural help
and maintainer minutes, Codex work minutes, extra source reads/time, waiting,
and strategic/authority intervention separately. The script measures acquisition
and Runtime durations only; its human_measurements remains null. Technical
tests, an isolated demonstration, integrated continuation and human product
acceptance are different evidence classes.

Prepare the later Gate 2 trial with two technical operators unfamiliar with
Runtime internals, one authorized native corpus and one existing-canon corpus.
Give them this guide; record all rescue and false blockers. No operators have
been contacted or counted. Founder-assisted research does not pass that gate,
