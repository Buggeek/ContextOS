# 5.5 — Context OS Runtime Maturity Model

## Purpose

This document defines the **Runtime Maturity Model** for Context OS.

Maturity is the canonical way to describe **how operational a Context OS
Runtime instance is** along five dimensions. Every Runtime instance, every
roadmap version, and every adoption engagement is anchored to a Maturity
Level.

This artifact supersedes the inline 5-level scale previously summarized in
[`5.3_COS_Runtime_Strategy.md`](5.3_COS_Runtime_Strategy.md).

---

## Dimensions

A Runtime is measured along five orthogonal dimensions:

| # | Dimension | What it measures |
|---|---|---|
| D1 | Organizational | How explicit and stable the organizational context is |
| D2 | Runtime | How operational the Runtime components are |
| D3 | Governance | How enforced contextual integrity is |
| D4 | Activation | How effectively context reaches humans, agents, systems |
| D5 | Autonomy | How much agentic action is delegated under accountability |

Each dimension has 5 levels. A Runtime's **overall level** is the **minimum**
of its dimension levels — coherence wins over local advancement.

---

## Levels

### Level 1 — Manual

Context is mostly implicit. Artifacts are produced by hand. Validation is
ad-hoc. No agents are operational.

| Dim | Indicator |
|---|---|
| D1 Organizational | Vision and constraints are declared but possibly informal |
| D2 Runtime | No Runtime services running; SSOT exists as files |
| D3 Governance | Reviews happen but are not codified |
| D4 Activation | Humans read SSOT directly; no IDE/agent surface integration |
| D5 Autonomy | Agents at L0–L1 only |

**Promotion gate to Level 2:** MOM complete, governance roster declared, at
least one Runtime component installed.

---

### Level 2 — Assisted

Runtime components are installed. Agents propose; humans approve. Validation
is automated for taxonomy and links.

| Dim | Indicator |
|---|---|
| D1 Organizational | MOM complete; Hypothesis vs Verified tagging applied |
| D2 Runtime | Assessment, validation, bootstrap, and construction components active in `assist` mode |
| D3 Governance | DoR/DoD enforced on every change; Accountability Ledger live |
| D4 Activation | At least one Activation surface (IDE or CLI) actively used |
| D5 Autonomy | Agents at L2 on draft surfaces; L1 elsewhere |

**Promotion gate to Level 3:** drift detection running, mission lifecycle in
routine use.

---

### Level 3 — Managed

Continuous maintenance is in place. Drift is detected and remediated.
Missions run through the Mission Lifecycle end-to-end.

| Dim | Indicator |
|---|---|
| D1 Organizational | Verified context dominates; Hypotheses are tracked and burned down |
| D2 Runtime | Context Health, drift detection, and governed construction loops run routinely |
| D3 Governance | Governance Lifecycle event-driven; audit trail queryable |
| D4 Activation | Multiple Activation surfaces; memory and prior-art signals support routine work |
| D5 Autonomy | Execution Agent at L3 on draft surfaces; promotion criteria documented |

**Promotion gate to Level 4:** Dynamic Team Assembly operating routinely; at
least one capability promoted to L4 with full ledger trail.

---

### Level 4 — Adaptive

Dynamic agent teams operate against evolving context. Capability pools and
team assembly are routine. The organization measurably benefits from agent
leverage while preserving accountability.

| Dim | Indicator |
|---|---|
| D1 Organizational | Strategy adapts using validated learnings within a documented cadence |
| D2 Runtime | Runtime supports mission-scoped orchestration at scale |
| D3 Governance | Policy inheritance enforced; violations auto-route to Governance Lifecycle |
| D4 Activation | Activation Layer serves both IDE and workflow targets |
| D5 Autonomy | Selected capabilities at L4; L5 considered only under explicit governance review |

**Promotion gate to Level 5:** sustained Level 4 with no contextual integrity
regressions across two consecutive evaluation periods.

---

### Level 5 — Organizational Intelligence

Context is operational infrastructure. Humans and intelligent systems
collaborate through a shared contextual model. The Runtime adapts itself
within governance.

| Dim | Indicator |
|---|---|
| D1 Organizational | Strategy, product, and operations co-evolve through measurable context loops |
| D2 Runtime | Self-instrumented; provides decision support to leadership |
| D3 Governance | Governance is itself adaptive within hard policy bounds |
| D4 Activation | Activation reaches humans, agents, and systems uniformly |
| D5 Autonomy | Limited L5 capabilities permitted under continuous audit |

## Roadmap Anchoring

Every roadmap version in
[`5.4_COS_Product_Roadmap.md`](5.4_COS_Product_Roadmap.md) targets an explicit
Maturity Level floor:

| Roadmap version | Target floor | Notes |
|---|---|---|
| v0.1 Framework Foundation | L1 | Framework only; no Runtime |
| v0.2 Framework Hardening | L1 | Canonical structure; SSOT complete |
| v0.3 Context Readiness | L1 with L2 entry signals | Read-only assessment, ValidatorEngine, CLI validate/readiness surface |
| v0.4 Guided Bootstrap | L2 entry | Minimum governed Context OS home can be created from readiness findings |
| v0.5 Context Construction | L2 | Structured Discovery + Builder drafts + Validator promotion gate |
| v0.6 Context Activation | L2 (D4 raised) | At least one operational surface consumes governed context |
| v0.7 Context Health & Learning | L3 | Drift detection and remediation loops routine |
| v0.8 Organizational Memory | L3 (D1/D2 raised) | Memory tiers and prior-art retrieval operational |
| v0.9 Contextual Reasoning | L4 entry | Governed reasoning and dynamic capability assembly under audit |
| v1.0 Organizational Context Runtime | L5 | Full Assess -> Bootstrap -> Construct -> Activate -> Learn -> Reason loop |

---

## Evaluation Procedure

Maturity evaluation is a Governance Lifecycle event.

1. Context Guardian compiles current indicators per dimension.
2. Each indicator is scored against the table above.
3. The overall level is the minimum dimension level.
4. Result is recorded as a Decision Record in SSOT.
5. Promotion or regression triggers the relevant lifecycle action.

Evaluation cadence: per release minimum; on-demand on request of Maintainer or
Runtime Owner.

---

## Anti-Patterns

- Reporting maturity as the maximum dimension level (false advancement).
- Skipping promotion gates.
- Granting L4/L5 autonomy without sustaining Level 3 maturity.
- Treating maturity as a marketing claim rather than an operational measure.
