# 3.1 — Agentic Operating Model (AOM)

The Agentic Operating Model defines **how work happens** in a system where humans and agents collaborate under a shared context.

It is not a technical framework.  
It is not an orchestration library.  
It is a **Way of Work**.

The AOM translates Context OS from a contextual foundation into **coordinated, accountable action**.

---

## Purpose of the Agentic Operating Model

As agents enter real operational workflows, organizations face a new risk:

- intelligence without accountability,
- automation without governance,
- execution without shared criteria.

The Agentic Operating Model exists to define:
- who interacts with whom,
- who is responsible for outcomes,
- and how decisions are made and validated.

Without an operating model, agents amplify chaos.  
With one, they amplify coherence.

---

## Design Principles

The AOM is built on a small set of non-negotiable principles:

### Single Interface Principle
There is exactly **one interaction point** between the system and the user.

This avoids:
- contradictory responses,
- fragmented decision-making,
- and unclear responsibility.

---

### Explicit Accountability
Every outcome has a clear owner.

Agents can assist, execute, or validate —  
but responsibility is never ambiguous.

---

### Context-First Execution
No task is executed outside of explicit context.

If context is missing, unclear, or contradictory:
- execution pauses,
- clarification is requested,
- or the task is escalated.

---

### Evidence over Trust
Agents are evaluated by outcomes and traceability, not perceived intelligence.

Confidence without evidence is treated as risk.

---

### Human-in-the-Loop by Design
Humans are not fallback mechanisms.

They are:
- intent setters,
- decision authorities,
- and system governors.

---

## Separation of Concerns: Context vs Operation

Context OS and the Agentic Operating Model operate at different layers.

### Context OS defines:
- purpose and intent,
- constraints and policies,
- shared language,
- and organizational reality.

### The AOM defines:
- how work is performed,
- how agents collaborate,
- and how accountability is enforced.

The AOM **consumes** Context OS.  
It does not redefine or duplicate it.

---

## Roles and Interaction Model

The AOM establishes a clear interaction hierarchy:

1. **User (Human)**
2. **Orchestrator (Primary Agent)**
3. **Specialized Agents**
4. **Subagents / Skills (optional, future)**

A critical rule applies:

> The user never interacts directly with execution agents.

This preserves coherence, traceability, and governance.

---

## The Orchestrator Role

The Orchestrator is the central role of the Agentic Operating Model.

It acts as:
- the system’s single interface,
- the translator of human intent,
- and the final integrator of results.

### Core responsibilities

The Orchestrator is responsible for:
- understanding user intent,
- validating requests against context,
- decomposing missions into tasks,
- assembling agent teams,
- integrating outputs,
- and deciding when human intervention is required.

### What the Orchestrator does not do

The Orchestrator does not:
- perform heavy execution work,
- bypass context constraints,
- or make unilateral strategic decisions.

It coordinates. It does not dominate.

---

## Agent Roles as Executable Job Descriptions

In the AOM, agents are not defined by prompts.  
They are defined by **roles**, equivalent to organizational job descriptions.

Each agent role must explicitly define:
- purpose,
- responsibilities,
- decision boundaries,
- quality criteria,
- and performance metrics.

Agent roles are:
- versioned,
- reusable,
- and auditable.

This allows organizations to reason about agents with the same rigor applied to human roles.

---

## Skills, Tools, and Configuration

The AOM separates stable structure from flexible execution.

### Roles
Define responsibility and accountability.  
They change infrequently.

### Skills
Define capabilities:
- reasoning,
- analysis,
- synthesis,
- validation.

Skills do not decide. They enable.

### Tools
Define access to systems and resources:
- repositories,
- databases,
- APIs,
- operational interfaces.

Tools are environment-dependent.

### Missions
Define the actual work:
- tasks,
- stories,
- incidents,
- decisions.

Missions are dynamic and ephemeral.

This separation allows teams to reconfigure execution without redefining roles.

---

## Human-in-the-Loop Model

Human participation is explicit and intentional.

Humans intervene at three moments:

### 1. Intent Definition
Humans define:
- goals,
- constraints,
- and priorities.

The Orchestrator confirms understanding before execution.

---

### 2. Critical Decision Validation
Humans validate:
- strategic trade-offs,
- unresolved ambiguities,
- and high-impact decisions.

Agents never assume authority by default.

---

### 3. Governance and Learning
Humans:
- evaluate outcomes,
- adjust context,
- refine roles and metrics.

The system learns through governance, not automation alone.

---

## Operational Metrics and Governance

The AOM is governed through observable signals.

Typical metrics include:
- rate of clarification requests,
- retrabajo frequency,
- deviation from context,
- escalation volume,
- alignment with True North metrics.

Agents are evaluated by:
- consistency,
- reliability,
- and contextual alignment.

Not by confidence or verbosity.

---

## Continuous Construction and Operation

In real systems, construction and operation are inseparable.

The AOM assumes:
- context evolves continuously,
- execution feeds back into context,
- and both are governed through loops.

Backlog changes update context.  
Context changes constrain backlog.

This loop is intentional and explicit.

---

## Evolution Path

The AOM evolves incrementally:

- **v0** — Orchestrator + basic agents
- **v1** — dynamic team composition
- **v2** — specialized subagents
- **v3** — multi-domain orchestration

No technical implementation is implied by this progression.

---

## Summary

The Agentic Operating Model defines **how intelligence is operationalized**.

Without it:
- agents become uncontrolled executors,
- humans lose visibility,
- and context erodes.

With it:
- responsibility is clear,
- decisions are traceable,
- and intelligence scales without chaos.

Context OS defines *what matters*.  
The AOM defines *how it works*.
