# Context OS Document Taxonomy
## Version 1.0

This document defines the minimum viable taxonomy required to implement Context OS.

The objective is not exhaustive documentation.
The objective is structural coherence.

All documents in Context OS must belong to a defined type.

No orphan documents are allowed.

---

## Compliance Profiles (SSOT)

This taxonomy distinguishes between two compliance profiles for **SSOT trees** (e.g. an organization’s `SSOT/` folder).

- **minimal**: Early adoption mode. Documents SHOULD be short, but MUST make ownership, intent, and dependencies explicit.
- **strict**: Governed mode. Documents MUST include all **Mandatory Fields** listed for their type.

This document describes **strict** requirements by default.
Examples and templates may explicitly declare `minimal` where appropriate.

---

# 1. Taxonomy Overview

Context OS v1.0 defines the following document categories:

0. Foundational Documents
1. Strategic Layer
2. Business Layer
3. Product Layer
4. Architecture Layer
5. Operational Layer
6. Governance Layer
7. Execution Layer
8. Feedback Layer

Each category has specific document types.

---

# 2. Foundational Documents (Prefix: 0.x)

# 11. Naming Conventions

Rules:

- Prefix defines layer.
- Numeric ordering defines hierarchy.
- Underscore separates words.
- CamelCase avoided for file names.
- Each file includes version in header.

Example:

P.5_Epic_User_Authentication.md

---

# 12. Cross-Reference Rules

Every document must:

- Link upward (parent layer)
- Link downward (dependent layer)
- Link sideways (related artifacts)

No document exists without relational context.

Broken links = structural decay.

---

# 13. Versioning Rules

Each document must include:

- Version number
- Last updated date
- Change summary
- Author

Major changes:
Increment X.0

Minor structural updates:
Increment 0.X

Editorial updates:
Increment 0.0.X

---

# 14. Minimum Operational Map (MOM) Requirement

For v1.0 adoption, the following documents are mandatory:

- S.1_Vision.md
- P.1_Product_Map.md
- A.1_System_Map.md
- A.4_Data_Entities.md
- G.1_Definition_of_Ready.md
- G.2_Definition_of_Done.md

These define the Minimum Operational Map.

No orchestration layer should operate without MOM defined.

---

# 15. Anti-Entropy Rule

No new artifact may be created outside taxonomy.

If a new document type is needed:

- It must be defined in this taxonomy.
- It must include mandatory fields.
- It must maintain cross-layer traceability.

Taxonomy evolution must be governed.

---

# 16. Summary

Taxonomy is not bureaucracy.

Taxonomy is structural clarity.

Clarity enables:

- Reliable execution
- Safe agentic orchestration
- Organizational memory
- Sustainable velocity

Without taxonomy, context fragments.

With taxonomy, context compounds.
