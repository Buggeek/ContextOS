# 1.5.9 - Context Activation Package Contract
## Version: 0.1.0
Last Updated: 2026-08-11
Owner: Context OS Maintainers
Status: active

---

## Purpose

Define the minimum runtime contract for activating canonical Context OS context
into a mission-bound working package.

The package answers:

```text
Which canonical context should this consumer use for this goal or mission, and
how can that working context be invalidated if source truth changes?
```

---

## Schema

```text
contextos.activation.package/1
```

Package drift checks emit:

```text
contextos.activation.package_check/1
```

Package-backed handoffs emit:

```text
contextos.activation.handoff/1
```

Handoff drift checks emit:

```text
contextos.activation.handoff_check/1
```

---

## Lifecycle Position

```text
Canonical Context
-> Activation Selection
-> Working Context Package
-> Consumer
-> Execution
-> Evidence / Feedback
-> Context Update Candidate
```

This contract covers only:

```text
Canonical Context -> Activation Selection -> Working Context Package
```

`contextos.activation.handoff/1` adds a compact consumer-facing bridge from a
valid package to execution. It does not add new source authority.

---

## Required Fields

| Field | Requirement |
|---|---|
| `schema` | Must equal `contextos.activation.package/1` |
| `id` | Stable package id derived from package identity payload |
| `identity_hash` | Stable hash of goal, consumer, source fingerprint, canonical sources, and boundaries |
| `goal` | Human-readable goal plus optional Mission Packet id |
| `consumer` | Consumer type, audience/surface, allowed permissions, and prohibited permissions |
| `canonical_sources` | Included source paths, hashes, authority tiers, and lifecycle states |
| `working_context` | Ordered derived context items for the consumer |
| `source_fingerprint` | Stable hash over included canonical source identities |
| `freshness` | Source count, Validator gate evidence, and generation freshness |
| `provenance` | Generator, source authority statement, and evidence lineage |
| `context_gaps` | Missing, unsafe, stale, or cautionary context conditions |
| `validator` | Embedded Validator gate summary |
| `invalidation` | Conditions and source hashes that invalidate the package |
| `boundaries` | Canonical-vs-working-context guarantees |
| `constraints` | No-mutation and no-parallel-SSOT guarantees |

---

## Handoff Required Fields

| Field | Requirement |
|---|---|
| `schema` | Must equal `contextos.activation.handoff/1` |
| `id` | Stable handoff id derived from package, consumer, Mission, sources, authority, constraints, and invalidation payload |
| `identity_hash` | Stable hash of the handoff identity payload |
| `source_package` | Exact package id, hash, optional package ref, schema, and source fingerprint |
| `package_check` | Current `contextos.activation.package_check/1` evidence |
| `consumer` | Consumer permissions inherited from the package |
| `mission` | Goal, Mission id, and binding inherited from the package |
| `working_instruction` | Compact universal instruction for using the package-backed context |
| `selected_context` | Source paths, hashes, roles, authority tiers, lifecycle states, titles, owners, and provenance |
| `exclusions` | Counted excluded sources with a bounded sample and truncation metadata |
| `known_gaps` | Package gaps carried forward without hiding uncertainty |
| `authority` | Allowed/prohibited permissions and explicit no-expansion boundary |
| `constraints` | No-SSOT, no-full-content-copy, no-write, no-mutation, and no-adapter guarantees |
| `freshness` | Package validity, current/package fingerprints, and Validator gate evidence |
| `invalidation` | Conditions and source hashes that invalidate the handoff |
| `evidence_and_exit_conditions` | Minimum Mission evidence obligations for a consumer |
| `result` | `handoff_ready`, invalidation state, and failed checks |

The handoff may summarize and point to canonical sources. It must not duplicate
full canonical content unnecessarily.

---

## Handoff Check Required Fields

| Field | Requirement |
|---|---|
| `schema` | Must equal `contextos.activation.handoff_check/1` |
| `handoff` | Checked handoff id, identity hash, Mission, and consumer |
| `source_package` | Handoff-bound package identity and optional package ref |
| `current_source_fingerprint` | Stable hash of currently observed selected source identities |
| `validator` | Embedded Validator gate summary |
| `checks` | Handoff identity, selected source hashes, Validator gate, package ref, package identity, and optional package check evidence |
| `result` | Validity, invalidation state, and failed checks |
| `constraints` | Read-only, no-mutation, no-parallel-SSOT, and no-selection-regeneration guarantees |

`contextos.activation.handoff_check/1` validates a saved handoff as a derived
working-context object. It must not regenerate activation selection or silently
reinterpret the Mission context.

---

## Consumer Permissions

An activation package may grant only:

```text
read_canonical_context
use_working_context
```

It must prohibit:

```text
mutate_canonical_context
promote_context
delegate_authority
```

Future adapters may add surface-specific permission details, but they must not
weaken these base restrictions.

Handoffs inherit these permissions. A handoff must not expand package authority
or grant write, promotion, delegation, or mutation privileges.

---

## Boundary Rules

The Working Context Package:

- is derived working context,
- is not SSOT,
- must not become canonical truth by being generated,
- must preserve source paths and hashes,
- must preserve authority tiers,
- must preserve lifecycle states,
- must expose gaps and warnings,
- must be invalidated when source hashes or Validator gates change.

Canonical sources remain authoritative.

A handoff is a package-backed operating brief. It may tell a consumer what to
do next, which sources govern the work, which gaps remain, and when to
revalidate. It is still derived working context, not SSOT.

---

## Validator Gate

Activation must be blocked when Validator gate reports errors or fatals.

Warnings may appear as context gaps, but do not block activation by themselves.

---

## Prohibited Behavior

This contract does not allow:

- canonical context mutation,
- draft creation,
- promotion,
- Knowledge Engine reasoning,
- Context Graph runtime,
- autonomous agent orchestration,
- external connectors,
- background synchronization,
- hidden SSOT copies.

---

## Package-First Mission Use

A self-hosted Mission may use an Activation Package as authoritative working
context only when:

1. the package is generated or resolved for the exact goal/Mission and
   consumer,
2. `contextos.activation.package_check/1` is valid immediately before use,
3. the Mission records the package id and identity hash,
4. the Mission records selected canonical sources and exclusions,
5. the Mission records context gaps and whether additional repository context
   was needed,
6. additional context is limited to selected sources or objective gaps,
7. any source mutation during execution is treated as package invalidation,
8. Mission evidence records whether a fresh package is required after changes.

The package is authoritative as working context only. It does not replace the
canonical sources it references.

## Implementation

Initial implementation:

```text
tools/activation/activation_engine/package_engine.py
```

Initial public API:

```python
from activation_engine.package_engine import ContextActivationPackageEngine

package = ContextActivationPackageEngine(".").run(
    goal="Plan the next mission",
    consumer="codex",
    mission_id="V06-CONTEXT-ACTIVATION-PLAN-001",
)
```

Initial Runtime CLI surface:

```bash
./contextos activate \
  --root . \
  --goal "Plan the next mission" \
  --consumer codex \
  --mission-id V06-ACTIVATION-PACKAGE-CLI-001
```

Package check surface:

```bash
./contextos activate \
  --root . \
  --check-package /tmp/contextos-activation-package.json \
  --format json
```

Package-backed handoff surface:

```bash
./contextos activate \
  --root . \
  --check-package /tmp/contextos-activation-package.json \
  --handoff
```

Handoff check surface:

```bash
./contextos activate \
  --root . \
  --check-handoff /tmp/contextos-activation-handoff.json \
  --format json
```

Fresh package plus handoff:

```bash
./contextos activate \
  --root . \
  --goal "Plan the next mission" \
  --consumer codex \
  --mission-id V06-ACTIVATION-HANDOFF-FORMAT-001 \
  --handoff
```

Exit codes:

| Code | Meaning |
|---|---|
| `0` | Package created, package check valid, handoff ready, or handoff check valid |
| `7` | Validator gate blocks activation, package check is invalidated, handoff not ready, or handoff check invalidated |
| `9` | Misconfiguration or invalid input |
