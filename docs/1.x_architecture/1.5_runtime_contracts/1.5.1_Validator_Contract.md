# 1.5.1 — Validator Contract

## Purpose

The Validator is the Runtime component responsible for protecting **contextual
integrity**. It runs a declared rule set against the SSOT, the Context Graph,
and the runtime manifest, and emits a structured **Context Health Report**.

This contract specifies what the Validator must accept, produce, and
guarantee. Implementation is delegated to **EPIC-007 Validator Engine**.

---

## Scope

The Validator validates:

- File structure under `docs/`, `SSOT/`, `ops/`, `templates/`.
- Naming and taxonomy conventions
  ([`2.0`](../../2.x_taxonomy/2.0_COS_Document_Taxonomy.md)).
- Cross-reference integrity (links, anchors, paths).
- SSOT MOM completeness.
- Hypothesis vs Verified tagging coverage on product artifacts.
- Authority Model bindings against
  [`3.6`](../../3.x_operation/3.6_COS_Human_Agent_Authority_Model.md).
- Drift between Discovery output and SSOT (when Discovery data is available).

The Validator does **not** evaluate semantic correctness of prose.

---

## Modes

| Mode | Use |
|---|---|
| `install-check` | Run during installation; checks scaffolding and manifest only |
| `pre-bootstrap` | Run before Bootstrap Step 8; checks source registry, governance roster |
| `full` | Full SSOT + graph validation (default for `contextos validate`) |
| `gate` | Same as `full` but exits non-zero on any `severity >= error` |

---

## Rule Categories

Each rule belongs to exactly one category and has a stable identifier
`<category>.<rule>`.

| Category | Example rules |
|---|---|
| `structure` | required folders present; file naming matches taxonomy prefix |
| `naming` | `Context OS` prose vs `ContextOS` identifier vs `contextos` CLI |
| `links` | every relative link resolves; no anchors to missing headings |
| `taxonomy` | doc class matches its folder; H1 prefix matches filename prefix |
| `mom` | MOM artifacts present in SSOT; required fields populated |
| `hypothesis` | every product artifact declares status, success criterion, kill criterion |
| `authority` | every active agent capability has a declared autonomy level |
| `ownership` | every SSOT artifact declares an owner |
| `drift` | Discovery facts and SSOT entries agree (when Discovery data available) |
| `governance` | DoR/DoD presence; Accountability Ledger schema validity |

---

## Severity

| Severity | Meaning | Default exit behavior |
|---|---|---|
| `info` | Informational; no action required | exit 0 |
| `warn` | Should be addressed; non-blocking | exit 0 in `full` and `gate` |
| `error` | Must be addressed; blocking | exit non-zero |
| `fatal` | Validator cannot continue (corrupt input, missing manifest) | exit non-zero immediately |

---

## Inputs

```yaml
inputs:
  mode: install-check | pre-bootstrap | full | gate
  root: <absolute path to repository root>
  rules: optional list of <category>.<rule> to include or exclude
  manifest: path to Runtime manifest (defaults to .contextos/manifest.yaml)
  graph: optional path or handle to Context Graph snapshot
  discovery: optional path or handle to Discovery output bundle
```

The Validator must read the inputs once and must not mutate them.

---

## Outputs

### Context Health Report (machine)

```yaml
report:
  schema: contextos.validator.report/1
  generated_at: <iso8601>
  mode: <mode>
  root: <root>
  summary:
    rules_run: <int>
    info: <int>
    warn: <int>
    error: <int>
    fatal: <int>
    exit_code: <int>
  findings:
    - id: <ulid>
      rule: <category>.<rule>
      severity: info | warn | error | fatal
      message: <string>
      path: <relative path or null>
      line: <int or null>
      anchor: <string or null>
      evidence: <object or null>
      suggested_fix: <string or null>
```

### Context Health Report (human)

A rendered markdown summary with: counts per severity, top 10 findings, and a
link to the full machine report. Implementations may render additional views.

### Side outputs (optional)

- A graph snapshot fingerprint (when graph input provided).
- A diff against the previous report when a baseline is supplied.

---

## Exit Codes

| Code | Meaning |
|---|---|
| 0 | No findings at or above the active blocking threshold |
| 7 | One or more `error` findings (blocking threshold reached) |
| 8 | One or more `fatal` findings |
| 9 | Validator misconfiguration (bad rules selection, invalid manifest) |

The codes align with [`1.5.2 CLI Contract`](1.5.2_CLI_Contract.md).

---

## Guarantees

- **Determinism:** identical inputs produce identical reports.
- **Idempotence:** the Validator never modifies the repository.
- **Traceability:** every finding cites its rule id and its origin location.
- **Compositionality:** rule sets can be subset/superset selected without
  changing rule semantics.
- **Observability:** the Validator emits a `validation.run` event per
  invocation
  (see [`1.5.5 Runtime Event Model`](1.5.5_Runtime_Event_Model.md)).

---

## Authority

The Validator runs at autonomy **L4 read-only** (auditor). It never proposes
mutations. Suggested fixes are advisory and require a separate mission to
apply.

---

## Versioning

The report schema is versioned (`contextos.validator.report/<n>`). Breaking
changes increment `<n>` and require a Governance decision.
