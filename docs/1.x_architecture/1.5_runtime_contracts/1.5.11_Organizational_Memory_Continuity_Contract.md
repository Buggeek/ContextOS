# 1.5.11 - Organizational Memory Continuity Contract

## Purpose

This contract defines the first read-only Organizational Memory capability for
Context OS.

It enables an actor to inspect continuity across governed Missions, decisions,
evidence, outcomes, learning, context-state transitions, explicit
supersession, and unresolved gaps without creating a second SSOT or inferring
organizational truth from history.

The machine report schema is:

```text
contextos.memory.continuity_report/1
```

---

## Product Questions

The report must help answer:

- What happened?
- What was decided and why?
- Which evidence and outcomes were recorded?
- What was learned?
- What remains current, historical, superseded, or unknown?
- Which prior Mission records may be relevant to the active Mission?
- Which continuity, retention, or temporal gaps remain unresolved?

The report may identify prior art or pattern candidates. It must not claim
that retrieved history is applicable, useful, verified, or canonical without
separate evidence and governance.

---

## Boundary

Organizational Memory is a governed continuity function over authoritative and
governed sources. The report is a derived view.

```text
Canonical Context + Governed Mission Records + Evidence + Learning
-> Memory Continuity Selection
-> Derived Continuity Report
-> Human or Runtime Consumer
```

The report:

- is read-only;
- does not become SSOT;
- does not copy authority from its sources;
- does not promote remembered content;
- does not reinterpret missing history;
- does not implement retention, deletion, compaction, or forgetting;
- does not require a Context Graph, GraphRAG, embeddings, or a Knowledge
  Engine.

---

## Foundational Memory Forms

The first runtime supports these distinct forms:

| Form | Meaning | Minimum source |
|---|---|---|
| `mission` | Governed episode and execution boundary | Mission Packet |
| `decision` | Explicit recorded choice and rationale | Decision section or Decision Record |
| `evidence` | Recorded support or validation | Evidence section or evidence artifact |
| `outcome` | Explicit result or release outcome | Outcome or release-decision section |
| `learning` | Recorded learning that remains non-canonical | Learning section |
| `context_state` | Explicit organizational or release-state transition | Release-cut or context-version evidence |

Evolution Inbox records are preserved separately because deferred ideas,
risks, opportunities, hypotheses, and supersession state are not
interchangeable with Mission outcomes or canonical context.

Procedural memory and consolidated patterns are deferred. The report may emit
reviewable `pattern_candidates`, but they remain derived suggestions and
hypotheses.

---

## Truth Semantics

Every memory assertion preserves the canonical three-axis model:

| Axis | States |
|---|---|
| Epistemic support | `observed`, `declared`, `inferred`, `derived`, `unknown` |
| Governance lifecycle | `suggested`, `draft`, `reviewed`, `approved`, `canonical` |
| Strategic belief | `hypothesis`, `verified`, `deprecated` |

When a source does not explicitly declare an axis, the report uses `null`.
`recorded` is an index status outside these truth axes; it must not be invented
as an additional governance or strategic state.

Indexing an explicit source is `observed` evidence about that source. It does
not establish that the source statement is current organizational truth.

Prior-art relevance and recurring-pattern detection are `derived`,
`suggested`, and `hypothesis`. Repetition, recency, retrieval, or ranking never
promotes them.

---

## Temporal And Supersession Semantics

Each memory entry should preserve, where explicitly available:

- `valid_from`;
- `valid_to`;
- `observed_at`;
- `ceased_current_at`;
- current or historical applicability;
- the superseding record;
- the Mission, decision, evidence, or outcome responsible for a transition.

Missing temporal data must remain `null` and appear in
`temporal_unknowns`. File order, modification time, release number, or recency
must not be used to invent a validity window.

Supersession is emitted only from explicit source evidence. Therefore:

```text
Current != Historical
Historical != Invalid
Superseded != Deleted
Remembered != Canonical
Repeated != Proven useful
```

---

## Provenance And Identity

Every indexed entry includes:

- source path;
- source SHA-256 hash;
- source section where applicable;
- Mission and release identity where available;
- temporal metadata and explicit unknowns;
- truth semantics;
- retention class.

The report includes:

- a sorted source manifest;
- a deterministic `source_fingerprint` over that manifest;
- a deterministic `identity_hash` over source fingerprint, Mission/goal
  scope, memory-form counts, selected prior art, and supersession identities;
- an ID derived from the identity hash.

Generation time is excluded from report identity. Re-running against unchanged
inputs and scope must produce the same identity.

---

## Prior Art Selection

The first implementation may use bounded deterministic term overlap against
the Mission identity and goal.

Every result must expose:

- selection method;
- score;
- matched terms;
- source identity and hash;
- derived/hypothesis truth semantics.

This is explainable retrieval, not Knowledge interpretation. A selected item
is a prior-art candidate, not proof of applicability or usefulness.

---

## Pattern Candidates

A recurring pattern candidate may be emitted only when an explicit,
deterministic rule finds support in at least three distinct Mission learning
records.

Every candidate must:

- cite all supporting evidence;
- remain non-canonical;
- carry `derived`, `suggested`, and `hypothesis` semantics;
- prohibit automatic consolidation;
- route any accepted change through human review and the existing Context
  Construction lifecycle.

No process, workflow, skill, tool, role, agent, policy, or team pattern may be
created automatically from frequency.

---

## Retention And Forgetting

The first implementation reports retention classes but performs no retention
action.

Before destructive behavior exists, Governance must decide:

- ownership and authority;
- sensitivity and access;
- expiration and archival;
- legal/compliance holds;
- evidence preservation;
- reversible recovery where possible;
- deliberate forgetting criteria.

No memory may be silently deleted, compacted, expired, retained forever, or
promoted to canon by Runtime behavior.

The canonical decision model for these questions is defined by
[`1.5.13 Organizational Memory Retention Governance Contract`](1.5.13_Organizational_Memory_Retention_Governance_Contract.md).
Continuity reports expose policy gaps and inherited retention metadata but do
not resolve policy or change retention state.

## Authority And Side Effects

Generating and rendering this report requires read authority only.

The operation may not:

- mutate source artifacts or canonical context;
- change lifecycle, truth, supersession, or retention state;
- create a canonical decision, learning, or pattern;
- access external sources;
- trigger an agent, workflow, or Context Construction action.

Any future memory consolidation, retention, or forgetting operation requires a
separate contract and explicit human authority.

---

## Acceptance Criteria

- The report is deterministic for fixed sources, scope, and generation time.
- Report identity is stable when relevant state is unchanged.
- Every memory entry has source provenance and truth semantics.
- Missing temporal and supersession data remains explicit.
- Prior art is bounded and explainable.
- Pattern candidates remain non-canonical hypotheses.
- The Runtime performs no mutation or destructive retention behavior.
- Human and machine representations preserve the governance boundary.
