# 1.5.16 External Adoption Profile Contract

## Version: 1.1.0
Last Updated: 2026-09-05
Owner: Context OS Maintainers
Status: Canonical

---

## Purpose

`contextos.adoption.profile/1` lets Context OS operate over an organization's
existing governed canon without requiring Context OS filenames, folders,
taxonomy, repositories, or source-of-record technology.

The profile maps universal organizational capabilities to target-native
authority sources and declares which Runtime controls apply. It does not copy,
replace, or gain authority over the target canon.

```text
External Canon != Context OS Native Canon
External Canon != Adoption Profile
Adoption Profile != Working Context
Adoption Profile != Generated Report
```

---

## Canonical Boundary

The universal core understands organizational concepts, evidence, authority,
lifecycle, provenance, applicability, and invalidation. Target filenames and
target-specific controls live only in profile data or future adapters.

An Adoption Profile may be governed by Context OS adoption authority, but it
must preserve the target's source authority. It must state
`lifecycle.target_ssot: false`.

Suggested and unknown mappings are not target truth. A profile can recognize a
target source as canonical only when the mapping has observed, declared, or
deterministically derived support and an accountable authority owner.

---

## Machine Contract

Minimum top-level shape:

```yaml
schema: contextos.adoption.profile/1
id: adoption.profile.<target>.<version>
version: 1.0.0
target:
  id: <stable target id>
  name: <human name>
  scope: <repository|workspace|organization|system>
  kind: <target model>
lifecycle:
  state: <draft|reviewed|approved|canonical>
  target_ssot: false
  historical_reports_reinterpreted: false
authority:
  owner: <accountable profile owner>
  mapping_authority: <decision/evidence ref>
  target_authority_preserved: true
mappings: []
validation:
  rules: {}
activation:
  required_concepts: []
work_ownership:
  source_concepts: []
  lifecycle_semantics: {}
evidence_isolation:
  target_only: true
  host_context_is_evidence: false
invalidation:
  conditions: []
constraints:
  read_only: true
  parallel_target_ssot_created: false
```

Runtime loading deterministically calculates `identity_hash` from the complete
semantic payload. The binding exposed to derived reports contains schema, id,
identity hash, version, target, lifecycle, and the explicit non-SSOT boundary.

`work_ownership` is optional. When present, it identifies mapped concepts that
govern Goals, Missions, active work, ownership, lifecycle, blocking, return,
and closure evidence, and translates target-native lifecycle terms into the
bounded universal Work Ownership semantics. The mapping does not create target
work or make a target adopt Context OS's Mission format.

---

## Concept Mapping

Each mapping declares:

- a universal `concept`;
- support: `observed`, `declared`, `derived`, `suggested`, or `unknown`;
- confidence and unresolved ambiguity;
- whether supported sources are recognized as target canon;
- one or more source records, or an explicit true gap.

Each source record preserves:

- source-of-record locator;
- authority owner and authority tier;
- lifecycle/currentness and supersession state;
- permitted consumers and applicable operations;
- profile selection priority and activation role;
- evidence supporting the mapping;
- current source fingerprint when resolved.

The filesystem adapter uses repository-relative paths and SHA-256. Absolute or
escaping paths are rejected. Future source adapters must provide equivalent
stable locators and fingerprints; Git is implementation evidence, not the
universal identity model.

---

## Validation Applicability

Every selected Validator rule resolves independently to one state:

| State | Meaning |
|---|---|
| `universal` | Invariant applies across target representations. |
| `target_native` | Rule measures a target-relevant control. |
| `mapped_equivalent` | Target-native control provides functional equivalence. |
| `not_applicable` | Native rule does not govern this target. |
| `unknown` | Profile evidence cannot establish applicability. |

Enforcement is independently `blocking`, `advisory`, or `none`.

Validator reports must distinguish `passed`, `violated`,
`mapped_equivalent`, `not_applicable`, and `unknown`. A skipped rule must expose
the governing profile decision, rationale, equivalent-control references, and
whether a true gap remains. Context OS native rules must never apply by default
to an external target merely because the profile omitted a decision.

---

## Runtime Consumption

When a profile is active:

- **Inventory** reports mapped concepts and mapped source availability.
- **Readiness** scores functional capability evidence, not native-path
  conformity. Native manifests, MOM files, or SSOT directories are not implied
  requirements.
- **Activation** selects bounded target-native sources using mapped concepts,
  Goal/Mission relevance, authority, currentness, profile priority, and package
  limits.
- **Handoff** is sufficient only while its package is valid, selected context
  exists, and no blocking context gap remains.
- **Health** may cite only target evidence, profile mappings, target runtime
  observations, and explicitly authorized working evidence about that target.
- **Memory** recognizes target-native continuity forms without requiring E.4 or
  E.5 naming. Retention policy still governs exposure.
- **Reasoning** composes only profile-aware target evidence and remains explicit
  about unknowns or blocked inputs.
- **Work Ownership Resolution** uses only profile-mapped target-native sources,
  lifecycle semantics, exact relevance evidence, and a bounded coverage claim.
  Missing mappings fail closed as unknown rather than unowned.
- **Context Version** fingerprints the mapped governed target state and binds
  the exact profile identity without copying source content.

No profile automatically activates retrieved memory, grants authority, mutates
context, migrates a target, or generates a parallel SSOT.

---

## Evidence Isolation

External reports must not use Context OS's own Missions, releases, Health,
Construction records, or internal canon as evidence that the target is healthy
or governed. Host runtime schemas and rule identifiers may explain processing;
they are not target evidence.

Protected Memory candidates remain subject to policy-before-exposure. Profile
mapping does not authorize titles, paths, snippets, identities, hashes, or
sensitive metadata to be returned to a consumer.

---

## Invalidation

A material change to profile identity, version, target, mapping, applicability,
authority, selection, isolation, source lifecycle, or source fingerprint must
invalidate affected current-state plans and derived reports.

Captured historical Context Versions remain immutable historical identities.
A changed current profile makes their current applicability drifted; it does not
rewrite or erase their historically valid identity.

---

## Authority And Lifecycle

Profile creation or change requires an accountable human mapping decision. The
Runtime may inspect and deterministically derive fingerprints at read-only
authority. It may not infer a target owner, promote a suggested mapping, relax
policy, or mutate target canon.

Historical reports retain their original profile binding. A new profile creates
new derived identities; it does not silently reinterpret prior outputs.
