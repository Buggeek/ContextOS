# 1.5.12 - Organizational Memory Retrieval Contract

## Purpose

This contract defines bounded, explainable retrieval over the governed
Organizational Memory Continuity report.

It allows a human or machine consumer to request prior art for a Goal, Mission,
or bounded organizational question while preserving current canonical Context
as the only governing authority.

Machine schemas:

```text
contextos.memory.retrieval_result/1
contextos.memory.retrieval_check/1
```

---

## Product Question

The retrieval result answers:

> What relevant organizational prior art exists for this Goal or Mission, why
> is it relevant, what was true at that time, what superseded it, and how
> should it be interpreted now?

The result provides candidates and evidence. It does not decide that a
candidate is applicable, authoritative, causally useful, or safe to reuse.

---

## Activation And Memory Boundary

```text
Current Canonical Context
-> Context Activation Package
-> Governing Context

Governed Historical Records
-> Memory Continuity Report
-> Bounded Memory Retrieval
-> Prior-Art Candidates
```

Every retrieval result binds both paths:

- the Activation Package supplies current Governing Context;
- the Memory Continuity report supplies historical continuity;
- retrieved memory is not inserted into the Activation Package;
- retrieved memory never overrides current canonical Context;
- conflict resolution requires separate governed interpretation.

The retrieval result is not an Activation Package, SSOT, context version,
Decision Record, or canonical artifact.

---

## Required Query

```yaml
query:
  goal: <required bounded outcome>
  mission_id: <optional mission identity>
  question: <optional bounded organizational question>
  consumer: <human, codex, claude_code, ide_assistant, tool, or future consumer>
  limit: <1-50>
```

Changing any query field changes retrieval identity.

The consumer must not manually enumerate canonical files. Context Activation
selects Governing Context; Memory Retrieval selects prior art from structured
continuity.

---

## Bounded Selection

The first implementation uses deterministic structured term overlap.

Candidate inputs are Mission, Decision, Evidence, Outcome, Learning,
Context-state, Evolution Inbox, and non-canonical pattern-candidate memory.

For every selected item, the result exposes:

- normalized matched terms;
- memory-form priority;
- deterministic score;
- selection method and rationale;
- source path and hash;
- Mission and release association where available.

Selection is bounded by a result limit and source-diversity limit. Excluded
candidates preserve an explainable reason: active Mission self-record, no
explainable overlap, source-diversity limit, or bounded result limit.

Keyword frequency, recency, repetition, or rank do not confer authority.

---

## Candidate Semantics

Every selected item preserves:

- memory identity and form;
- title and source summary;
- temporal status, metadata, and unknowns;
- Mission and release lineage;
- truth-axis states;
- source provenance;
- explicit supersession, where known;
- retention class;
- current-context comparison state;
- applicability and authority state.

The first implementation sets applicability to `candidate`. A consumer must
inspect the source and current Governing Context before applying it as prior
art.

```text
Retrieved != Relevant without rationale
Relevant != Applicable
Applicable != Authoritative
Repeated != Useful
Historical != Invalid
Superseded != Deleted
Remembered != Canonical
```

---

## Current, Historical, And Superseded State

Temporal status is:

```text
current | historical | superseded | unresolved | unknown
```

- `current` means the source record is active; it does not make every assertion
  canonical.
- `historical` means the source episode is closed or temporally bounded; it
  does not mean invalid.
- `superseded` requires explicit supersession evidence.
- `unresolved` represents an open or deferred continuity record.
- `unknown` is used when current temporal state cannot be proven.

Absence of a supersession record is not proof of current validity.

Semantic conflict with current canonical Context remains `unknown` unless
explicit structured evidence establishes a boundary. The Runtime must not use
language-model interpretation to resolve it silently.

---

## Truth Axes

The result preserves the canonical axes independently:

| Axis | States |
|---|---|
| Epistemic support | `observed`, `declared`, `inferred`, `derived`, `unknown` |
| Governance lifecycle | `suggested`, `draft`, `reviewed`, `approved`, `canonical` |
| Strategic belief | `hypothesis`, `verified`, `deprecated` |

Missing source evidence for an axis remains `null`. Retrieval itself confers
no governance lifecycle or strategic verification.

---

## Identity And Provenance

The retrieval identity binds:

- exact query;
- Memory Continuity identity hash;
- Activation Package identity hash;
- selected memory identities;
- matched terms and deterministic scores.

Generation time is excluded from identity.

The result embeds the exact Activation Package required for later validity
checking and records the exact Memory Continuity identity and source
fingerprint. It must never regenerate changed intent under an existing
retrieval identity.

---

## Freshness And Invalidation

A saved result is invalid when:

- retrieval identity or query changes;
- bound Memory Continuity identity or source fingerprint changes;
- the bound Activation Package becomes invalid;
- selected canonical source hashes change;
- the selected memory set or selection rationale changes;
- supersession, temporal, retention, permission, or evidence relationships
  change.

`contextos.memory.retrieval_check/1` reports retrieval identity validity,
Activation Package validity, continuity-state equality, selection equality,
failed checks, and explicit `valid` / `invalidated` state.

Check never mutates or replaces the saved result.

## CLI Surface

```text
contextos memory --goal <text> [--mission-id <id>] [--question <text>]
                 [--consumer <type>] [--limit <1-50>]
                 [--format text|human|json] [--json-out <path>]

contextos memory --check-retrieval <retrieval.json>
                 [--format text|human|json] [--json-out <path>]
```

JSON stdout must contain only the machine report.

Exit codes:

- `0`: retrieval generated with a non-blocking Activation gate, or a saved
  retrieval remains valid;
- `7`: blocking Validator errors or invalidated saved retrieval;
- `8`: fatal Validator findings;
- `9`: missing/invalid root, query, input schema, limit, or JSON.

---

## Authority And Side Effects

Retrieval and checking require read authority only. They may not:

- mutate canonical Context or Memory sources;
- modify an Activation Package;
- promote historical context;
- infer applicability, authority, usefulness, or semantic conflict;
- execute retention or forgetting;
- create processes, skills, tools, roles, agents, policies, or canonical
  knowledge from pattern candidates;
- invoke GraphRAG, embeddings, a vector database, Knowledge reasoning,
  external services, or autonomous agents.

---

## Acceptance Criteria

- Human and machine consumers can request bounded Mission/Goal prior art.
- Every selected item has explainable rationale and provenance.
- Current Activation authority and historical Memory remain distinct.
- Applicability and usefulness are not inferred.
- Explicit supersession and temporal unknowns remain visible.
- JSON output is pure and parseable.
- A saved result validates when unchanged and invalidates on relevant drift.
- The operation is deterministic and read-only.
