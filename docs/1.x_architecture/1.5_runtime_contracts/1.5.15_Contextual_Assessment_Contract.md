# 1.5.15 Contextual Assessment Contract
## Version: 0.1.0
Last Updated: 2026-08-24
Owner: Context OS Maintainers

---

## Purpose

Define the first governed Contextual Reasoning surface. A Contextual Assessment
combines exact Runtime evidence into an explainable advisory view of the
current situation without becoming a Decision, authority, or canonical truth.

```text
Evidence != Observation != Interpretation != Inference != Hypothesis
!= Recommendation != Decision != Authority != Canonical Truth
```

---

## Product Question

Given the organization's current governed context, health, authorized memory,
historical context, and Goal, what is directly supported, what may reasonably
be interpreted, what remains unknown, and what should an accountable human
consider next?

---

## Inputs

A Contextual Assessment binds the following exact inputs where available:

- Goal and optional Mission;
- consumer, purpose, organizational mode, roles, and authority scope;
- current Activation Package selected by bounded Retrieval;
- Context Health report and optional Mission-use evidence;
- policy-aware Organizational Memory Retrieval;
- exact Context Versions and independent integrity/applicability checks;
- retention policies, memory metadata, and temporal evaluation basis.

Missing policy, authority, Context Version, evidence, or observability must be
represented as unknown or required evidence. Absence never means permission or
support.

confidence is prohibited unless separately justified by evidence.

---

## Reasoning Semantics

- **Observation** reports structured evidence without adding meaning.
- **Prior art** exposes only policy-authorized Memory and grants no current
  authority.
- **Context change** reports exact source-state difference; it does not infer
  semantic applicability.
- **Contradiction** requires explicit conflicting claim evidence. Absence of a
  proven contradiction is not proof of consistency.
- **Interpretation** is bounded meaning derived from cited evidence.
- **Hypothesis** is unverified and must remain labelled.
- **Recommendation** is advisory and cannot become a Decision automatically.
- **Unknown** preserves missing, withheld, unobservable, or unresolved state.
- **Required decision** identifies a human authority boundary.
- **Additional evidence** identifies what is needed before stronger reasoning.

---

## Authority And Safety

The initial engine operates at `L1_suggest`:

- it may inspect, derive bounded interpretations, form hypotheses, and
  recommend;
- it may not decide, approve, execute, mutate canonical context, change
  policy, or restore historical authority;
- policy-aware Retrieval must run before protected memory can influence the
  assessment;
- tampered Context Versions must be rejected;
- historical drift must not be presented as semantic invalidity;
- Health signals may inform reasoning but may not become truth by inclusion;
- output is a derived working view and never a second SSOT.

Consequential transitions must use the existing Decision, authority, Mission,
Context Construction, validation, and evidence lifecycle.

---

## Identity And Invalidation

Assessment identity is a deterministic SHA-256 binding over the normalized
query, exact input identities/hashes, Context Version checks, assertions, and
authority boundary. Timestamps and display root do not create a new logical
identity.

A saved assessment must not be reused when any bound Goal, Mission, consumer,
purpose, role, authority, package, Health evidence, Memory result, Context
Version, policy, retention state, temporal basis, permission, or source
fingerprint changes. A future check surface must recompute exact inputs and may
not silently reinterpret a saved assessment.

---

## Human Representation

The human report must show Goal, Mission, consumer, status, read-only boundary,
all reasoning categories as separate sections, evidence references, support
states, governing input identities, authority restrictions, and invalidation
conditions. Empty sections must say that no claim is supported by current
evidence rather than imply a negative fact.

---

## Explicit Non-Goals

- free-form organizational truth generation;
- automatic Decision, approval, execution, or canonical mutation;
- semantic historical applicability without evidence;
- GraphRAG, Context Graph, embeddings, vector databases, broad RAG, learned
  ranking, agents, or external connectors by default;
- consumer-specific UI or workflow orchestration.

Graph-aware retrieval remains optional until a controlled benchmark proves a
material failure of bounded structured Retrieval.

---

## Acceptance Criteria

1. Machine and human reports preserve all reasoning categories and evidence.
2. Identical exact inputs produce identical logical identity and output.
3. Operation is read-only.
4. Tampered Context Versions are rejected.
5. Policy-withheld relevant Memory remains unknown and unexposed.
6. Authorized Memory appears only as non-authoritative prior art.
7. Historical drift is distinct from current semantic applicability.
8. Recommendations remain non-canonical and non-decisional.
9. Tests and dogfood prove the authority and epistemic boundaries.
10. Existing released Runtime behavior remains compatible.
