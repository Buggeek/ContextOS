# 1.5.17 Work Ownership Resolution Contract

## Version: 0.1.0
Last Updated: 2026-09-05
Owner: Context OS Maintainers
Status: Canonical

---

## Purpose

Define the read-only derived Runtime view that determines whether a governed
need, signal, or candidate Goal is already addressed by current organizational
work before Context OS recommends parallel work.

```text
Need != Goal
Goal != Mission
Mission != Owner
Owner != Authority
Active != Current Canon
Eligibility != Authority
Resolution != SSOT
```

The target organization remains authoritative for its Goals, Missions,
workstreams, owners, lifecycle semantics, and return conditions.

---

## Inputs

A resolution binds:

- one explicit need identity, statement, scope, and evidence references;
- normalized Goal, Mission, workstream, initiative, or operation records;
- explicit `need_refs` connecting work to the need;
- owner, lifecycle, currentness, parent-work, authority, blocking, return, and
  evidence fields where available;
- exact material source identities, locators, and fingerprints;
- a governed coverage assertion over the material source set;
- the exact External Adoption Profile and work-semantic mapping when operating
  on a target-native canon.

The initial Runtime does not infer equivalent work from prose similarity.
Unmapped relevance, incomplete coverage, missing ownership, or unknown
lifecycle state remains unknown.

Complete coverage requires explicit authority status and evidence references.
For external targets, every material source concept and locator must be mapped
by the exact approved or canonical Adoption Profile with observed, declared,
or derived support; arbitrary caller labels and suggested mappings are
rejected. Filesystem locators and resolved paths must remain inside the target
root; traversal and symlink escape are rejected before source content is read.

## Lifecycle Semantics

The universal Runtime recognizes these bounded work states:

```text
active
awaiting_evidence
awaiting_human_decision
blocked
deferred
completed
closed
superseded
historical
unknown
```

External organizations may use different terms. Their Adoption Profile maps
target-native terms to these semantics without requiring Context OS filenames,
folders, Mission formats, or project-management systems.

Completed, closed, superseded, and historical work does not claim current
ownership. Unknown or conflicting current ownership blocks new-work
qualification but does not invent an owner or authority.

One coherent parent/child chain resolves the leaf as the current work owner
while preserving any parent state that controls the disposition and return
condition. Multiple branches or a cyclic chain remain an explicit conflict.

---

## Disposition Semantics

A resolution may derive:

- `QUALIFY_NEW_WORK` only when coverage is complete, all material sources are
  exact, and no current ownership exists;
- `OBSERVE_EXISTING_WORK`, `AWAIT_EVIDENCE`, `AWAIT_HUMAN_DECISION`,
  `BLOCKED_BY_CURRENT_OWNER`, or `WAIT_FOR_EXISTING_WORK` when one coherent
  current ownership chain exists;
- `OWNERSHIP_CONFLICT` when multiple current ownership branches exist;
- `OWNERSHIP_UNKNOWN` when evidence, coverage, state, or ownership is
  insufficient;
- `REANCHOR_REQUIRED` when material evidence is missing or changed.

No disposition creates, cancels, merges, schedules, assigns, supersedes, or
authorizes work. Context OS may withhold a parallel recommendation; an
accountable human retains every consequential decision.

---

## Decision-Time Currentness

Before a consequential ownership claim or new-work recommendation is reused,
the Runtime must recheck the exact material Goal, Mission, ownership,
lifecycle, return-condition, and coverage sources.

```text
Context snapshot exactness
!= repository tip
!= selected-source currentness
!= material organizational-state currentness
```

An unrelated repository-tip advance does not invalidate an otherwise exact
resolution. Any materially bound source change requires bounded re-anchor.
The prior resolution remains immutable historical evidence but loses current
recommendation eligibility.

Continuous polling and full repository reprocessing are not required.

---

## Contextual Reasoning And Mission Evidence

When supplied to `contextos.reasoning.assessment/1`, the exact current
resolution acts as a consequential recommendation gate:

- existing ownership prevents a parallel Goal or Mission recommendation;
- evidence-waiting and human-decision-waiting remain distinct;
- conflict or unknown ownership remains explicit;
- material drift requires re-anchor;
- `QUALIFY_NEW_WORK` means eligible for normal human qualification, never
  authorized creation.

`contextos.mission.context_use_evidence/1` may record that ownership resolution
and material-currentness checks occurred and that a duplicate recommendation
was prevented. It must not infer reduced cognitive burden, usefulness, or
avoided human intervention from that fact alone.

---

## Concurrency And History

The target organization may continue operating while Context OS reasons from a
governed snapshot. Historical exactness, current-source freshness, material
drift, and work ownership remain separate:

```text
Historical Resolution + Material Drift
-> historically valid evidence
-> current recommendation ineligible
-> bounded re-anchor required
```

A Context Version remains valid historical evidence after target advancement.
It does not restore the prior resolution's current authority.

---

## Acceptance Criteria

1. Resolution is deterministic for exact inputs, read-only, and derived.
2. Complete current coverage with no owner permits only normal qualification.
3. One current ownership chain prevents parallel work recommendation.
4. Evidence waits, human decisions, blocks, and deferrals remain distinct.
5. Historical, closed, and superseded work does not falsely block.
6. Conflicting or unknown ownership remains explicit and grants no authority.
7. Irrelevant repository advancement preserves material currentness.
8. Material source drift requires re-anchor before consequential reuse.
9. External profiles map target-native sources and lifecycle semantics.
10. Native Context OS behavior remains compatible when no resolution is used.

---

## Explicit Non-Goals

- project-management replacement;
- task scheduling or continuous monitoring;
- semantic work-equivalence inference;
- automatic Goal, Mission, owner, lifecycle, or canonical mutation;
- target-specific concepts in universal Runtime code;
- GraphRAG, orchestration, agents, or external connectors.
