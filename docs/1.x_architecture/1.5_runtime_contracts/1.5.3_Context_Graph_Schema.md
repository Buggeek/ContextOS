# 1.5.3 — Context Graph Schema

## Purpose

The Context Graph is a **derived, non-authoritative** representation of the
organization's context. It exists to make SSOT navigable, queryable, and
reasonable about for both humans and agents.

This contract specifies the graph's **schema**: node types, edge types,
identity rules, derivation rules, and invariants.

Authority remains with SSOT; the graph never overrides it.

---

## Identity

- Every node has a stable `id` (ULID).
- Every node carries `kind`, `source`, `derived_at`, `provenance`.
- `provenance` includes `from_artifact` (SSOT path or Discovery/Knowledge
  bundle reference), `derivation_rule_id`, and `confidence`.

Node ids are stable across rebuilds when the underlying `provenance.from_artifact`
is unchanged.

---

## Node Kinds

| Kind | Source | Notes |
|---|---|---|
| `artifact` | SSOT file | One per SSOT `.md` artifact |
| `section` | SSOT heading | Optional; produced when section-level reference is needed |
| `entity` | `A.4_Data_Entities` + Discovery | Business or data entity |
| `system` | `A.1_System_Map` + Discovery | Service, module, repository |
| `role` | `3.2_agent_system/roles/` + governance roster | Agent role or human role |
| `mission` | Mission Packets | One per declared mission |
| `decision` | Decision Records | Immutable once created |
| `policy` | Governance Protocol | Inheritance-aware |
| `hypothesis` | Product artifacts | Linked to verified evidence if promoted |
| `evidence` | Verification outputs | Cites a `hypothesis` and a `mission` |
| `event` | Runtime event stream | Optional projection; rolling window |
| `owner` | Governance roster | Person or team |

---

## Edge Kinds

Edges are typed and directional.

| Edge | Domain → Range | Meaning |
|---|---|---|
| `references` | artifact → artifact | Link or anchor |
| `depends_on` | system → system | Runtime or build dependency |
| `owns` | owner → (artifact \| system \| mission \| role) | Ownership |
| `derives_from` | * → * | Provenance of a derived node |
| `verifies` | evidence → hypothesis | Validation relationship |
| `decided_by` | decision → mission \| policy | Decision authority trail |
| `governed_by` | * → policy | Applicable policy |
| `inherits` | policy → policy | Policy inheritance |
| `assigned_to` | mission → role | Role assignment per mission |
| `produced` | mission → artifact | Mission output trail |
| `evolves` | * → * (typed timestamp) | Temporal evolution edge |

---

## Status Tags

Every node carries a `status`:

| Status | Use |
|---|---|
| `observed` | Discovered fact from a connected system |
| `inferred` | Derived from interpretation; lower confidence |
| `hypothesis` | Declared but not validated |
| `verified` | Validated by evidence + decision |
| `deprecated` | Superseded but retained for traceability |

The graph never silently drops `deprecated` nodes.

---

## Derivation Rules

A derivation rule has:

```yaml
rule:
  id: <stable id>
  from: <node kind or selector>
  produces: <node kind>
  conditions: <pattern>
  invariants: <list>
  authority_level: <minimum autonomy required to apply at runtime>
```

Rules are versioned. A rule version change triggers re-derivation of affected
nodes and a `graph.rederived` event.

---

## Invariants

The graph guarantees:

1. **SSOT precedence.** When the graph and SSOT disagree, the graph yields.
2. **No silent mutation.** Every node change emits an event.
3. **Acyclicity for derivation.** `derives_from` is acyclic.
4. **Ownership coverage.** Every `artifact`, `system`, `mission`, `role`
   node has at least one inbound `owns` edge or is flagged for the
   `ownership` Validator rule.
5. **Hypothesis closure.** Every `hypothesis` node either has a `verifies`
   edge from an `evidence` node within its declared window, or is reported
   to the Validator `hypothesis` category.
6. **Authority binding.** Every `mission` node references the role(s) and
   autonomy level(s) granted at execution time.

---

## Query Surface (informational)

The contract does not pin a query language. Implementers must support:

- Lookup by `id`.
- Traversal from a node by edge kind with depth limit.
- Subgraph extraction by node kinds and a root selector.
- Provenance trace from any derived node back to its SSOT sources.

---

## Lifecycle

```
build  →  validate  →  publish  →  observe  →  evolve  →  rebuild
```

Each transition emits an event
(see [`1.5.5 Runtime Event Model`](1.5.5_Runtime_Event_Model.md)):

- `graph.built`
- `graph.validated`
- `graph.published`
- `graph.observed.<kind>`
- `graph.evolved`
- `graph.rederived`

---

## Authority

The graph is a **read product**. Writes are not allowed through the graph
surface; all writes flow through SSOT and are re-derived. The graph runtime
runs at L4 read-only.
