# 1.5.2 — CLI Contract

## Purpose

The `contextos` CLI is the canonical human and automation entry point to the
Runtime. This contract specifies the command surface, argument shapes, output
shapes, exit codes, and authority bindings.

Implementation is delegated to **EPIC-008 Runtime CLI**.

---

## Design Principles

1. **Composable.** Each command has a single responsibility and returns
   structured output.
2. **Scriptable.** Every command supports `--format json` and writes results to
   stdout; logs go to stderr.
3. **Deterministic.** Same inputs + same repository state produce the same
   outputs.
4. **Authority-aware.** Commands declare which autonomy level they require to
   complete writes; reads default to L1.
5. **Idempotent where possible.** `init`, `sources add`, `governance set-roster`
   are idempotent.
6. **Observable.** Every invocation emits a `cli.run` event
   (see [`1.5.5 Runtime Event Model`](1.5.5_Runtime_Event_Model.md)).

---

## Global Conventions

```text
contextos [--root <path>] [--format text|json] [--quiet] [--verbose] <command> [args]
```

- `--root` defaults to current working directory.
- `--format json` returns JSON to stdout; default is `text`.
- All commands write logs to stderr; data to stdout.
- All commands set exit codes per the table in §Exit Codes.

## Command Surface

### `contextos init`

Produce a Guided Bootstrap plan.

```text
contextos init [--root <path>] [--format text|human|json] [--json-out <path>]
contextos init [--root <path>] --proposal [--format text|human|json] [--json-out <path>]
contextos init [--root <path>] --approval-record <proposal.json> [--format text|human|json] [--json-out <path>]
contextos init [--root <path>] --accept-approval <approval.json> --accepted-by <human> --accepted-role <role> [--format text|human|json] [--json-out <path>]
contextos init [--root <path>] --preflight <accepted.json> [--format text|human|json] [--json-out <path>]
```

**Current v0.4 effects:** none. The command must not create, modify, or
delete repository files. It converts the Context Readiness Assessment,
recommendations, and Validator summary into a bootstrap plan.

**Authority:** L4 read-only.

**Output:** Guided Bootstrap Plan report with schema
`contextos.bootstrap.plan/1`.

When `--proposal` is supplied, the command returns a read-only Bootstrap
Proposal report with schema `contextos.bootstrap.proposal/1`. A proposal freezes
the source plan hash, repository fingerprint, authority requirements, action
classifications, rollback metadata, and drift invalidation conditions. It does
not approve or authorize apply.

When `--approval-record <proposal.json>` is supplied, the command returns a
read-only Bootstrap Approval Record Draft with schema
`contextos.bootstrap.approval_record/1`. The draft binds a preserved proposal
to required authority, drift status, blockers, and a Decision Record draft. It
does not approve the proposal or authorize apply.

When `--accept-approval <approval.json>` is supplied, the command returns a
read-only Bootstrap Accepted Decision with schema
`contextos.bootstrap.accepted_decision/1`. Acceptance requires an explicit
human identity through `--accepted-by` and an explicit authority role through
`--accepted-role`. It verifies proposal identity, source plan identity,
repository fingerprint, proposal file hash, drift status, prohibited actions,
and required evidence before producing an embedded `contextos.decision/1`
Decision Record. It approves the preserved proposal as future apply intent, but
does not authorize or perform apply.

When `--preflight <accepted.json>` is supplied, the command returns a
read-only Bootstrap Apply Preflight report with schema
`contextos.bootstrap.apply_preflight/1`. Preflight verifies the accepted
decision, approval record, proposal, source plan binding, repository
fingerprint, authority, no-overwrite guarantees, rollback expectations, and
Validator gate, then freezes the exact executable mutation set. It may mark
apply eligible, but does not authorize or perform apply.

**Output (json):**
```yaml
{
  "schema": "contextos.bootstrap.plan/1",
  "read_only": true,
  "summary": {
    "ready_for_bootstrap": true,
    "required_action_count": 0,
    "skipped_action_count": 0,
    "blocked_action_count": 0,
    "manual_action_count": 0
  },
  "actions": []
}
```

**Exit codes:** 0 plan generated with no blocking validator errors; 7 plan
generated with embedded validator errors or preflight generated but not
eligible; 8 fatal validator findings; 9 misconfiguration.

Future write-capable bootstrap behavior must be exposed through an explicit
apply surface that consumes a fresh eligible preflight and requires explicit
human apply confirmation. Bare `contextos init` must remain safe to run as a
planning command.

Any future write-capable surface must satisfy
[`1.5.7 Bootstrap Apply Approval Contract`](1.5.7_Bootstrap_Apply_Approval_Contract.md)
before it may modify a repository.

### `contextos assess`

Run the Context Readiness Assessment for Release v0.3.

```text
contextos assess [--root <path>] [--format text|human|json] [--json-out <path>]
```

**Authority:** L4 read-only.

**Effects:** none. The command must not create, modify, or delete repository
files.

**Output:** Context Readiness Assessment report per
[`1.5.6 Context Readiness Assessment Contract`](1.5.6_Context_Readiness_Assessment_Contract.md).

**Exit codes:** 0 report generated; 8 fatal assessment failure; 9
misconfiguration; 64 usage error.

Low readiness is not a CLI failure. Readiness level and recommendations are
reported inside the output.

### `contextos sources <subcommand>`

Manage the Connector Manifest (Bootstrap Step 1).

```text
contextos sources add <type> <reference> [--scope read|read-write] [--owner <id>]
contextos sources list
contextos sources remove <id>
```

**Authority:** L2 (writes manifest).

**Output (json) for `list`:**
```yaml
{
  "sources": [
    { "id": "<ulid>", "type": "<type>", "reference": "<ref>", "scope": "<scope>", "owner": "<id>" }
  ]
}
```

**Exit codes:** 0 success; 2 source registration failure (connectivity, auth, schema).

---

### `contextos governance set-roster`

Declare initial governance roster.

```text
contextos governance set-roster
  --maintainer <id> [--maintainer <id>...]
  --product-owner <id>
  --runtime-owner <id>
```

**Authority:** L3 (gated on `--confirm` or interactive prompt).

**Idempotent:** yes (last write wins; previous roster archived in ledger).

**Exit codes:** 0 success; 3 invalid roster.

---

### `contextos scan`

Run Discovery (Bootstrap Step 3).

```text
contextos scan [--source <id>...] [--out <path>]
```

**Authority:** L2 (reads external systems; writes discovery output bundle).

**Output:** Discovery output bundle path on stdout.

**Exit codes:** 0 success; 4 scan failure (any registered source unreachable
unless `--skip-unreachable`).

---

### `contextos build-mom`

Build or update MOM drafts (Bootstrap Step 6).

```text
contextos build-mom [--from <discovery-bundle>] [--from-knowledge <bundle>]
                    [--out SSOT/]
```

**Authority:** L3 (writes SSOT drafts; requires governance roster present).

**Output:** list of MOM artifact paths produced, each with Hypothesis vs
Verified tagging metadata.

**Exit codes:** 0 success; 5 build failure (missing inputs, taxonomy violation).

---

### `contextos build-ssot`

Promote MOM drafts to SSOT (Bootstrap Step 7).

```text
contextos build-ssot [--accept-hypotheses <list>] [--reject <list>]
```

**Authority:** L3 (requires Product Owner approval for product artifacts).

**Output:** SSOT diff summary.

**Exit codes:** 0 success; 6 promotion failure (governance gate, validation).

---

### `contextos validate`

Run the Validator (Bootstrap Step 8 + routine use).

```text
contextos validate [--mode install-check|pre-bootstrap|full|gate]
                   [--rules <selector>]
                   [--baseline <prior-report>]
```

**Authority:** L4 read-only.

**Output:** Context Health Report (machine + human) per
[`1.5.1 Validator Contract`](1.5.1_Validator_Contract.md).

**Exit codes:** 0 / 7 / 8 / 9 per Validator Contract.

---

### `contextos health`

Convenience wrapper. Runs `validate --mode install-check` for installation
verification; `validate --mode full` after activation.

**Exit codes:** delegated to `validate`.

---

### `contextos activate`

Activate the Runtime and agents (Bootstrap Steps 9–10).

```text
contextos activate [--agents <role>...]
```

**Authority:** L3 (requires Runtime Owner approval).

**Output:** activation manifest including instantiated roles, autonomy levels,
and the first accepted Mission Packet (if any).

**Exit codes:** 0 success; 8 activation failure (validation gate, authority
not configured).

---

### `contextos mission <subcommand>` (forward-looking)

Reserved surface for the Mission Lifecycle. The contract surface is declared
here to prevent collision; full semantics live in
[`1.5.4 Mission Contract`](1.5.4_Mission_Contract.md).

```text
contextos mission new <intent-file>
contextos mission list [--status <status>]
contextos mission show <id>
contextos mission close <id>
```

**Authority:** L3 (writes Mission Packets and Accountability Ledger entries).

## Exit Codes (canonical)

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Reserved for future write-capable bootstrap failure |
| 2 | `sources` failure |
| 3 | `governance set-roster` failure |
| 4 | `scan` failure |
| 5 | `build-mom` failure |
| 6 | `build-ssot` failure |
| 7 | `validate` blocked findings |
| 8 | `assess` fatal, `validate` fatal, or `activate` failure |
| 9 | Misconfiguration |
| 64 | Usage error (bad args) |

## JSON Output Shape Discipline

Every `--format json` invocation returns a single top-level JSON object.
Commands with a canonical report contract may return that report object
directly, identified by its `schema` field. Other commands return either
`result` or `error`. Errors include `code`, `message`, `category`, and
optional `evidence`.

```yaml
{ "schema": "contextos.readiness.report/1", ... }
# or
{ "result": { ... } }
# or
{ "error": { "code": 2, "category": "sources", "message": "...", "evidence": {...} } }
```

## Authority Summary

| Command | Required autonomy | Notes |
|---|---|---|
| `init` | L4 read-only | Guided Bootstrap plan only in v0.4 |
| `assess` | L4 read-only | Readiness assessment; no writes |
| `sources *` | L2 | Manifest writes |
| `governance set-roster` | L3 | Confirmation gate |
| `scan` | L2 | Read external, write bundle |
| `build-mom` | L3 | Writes SSOT drafts |
| `build-ssot` | L3 | Promotes drafts; PO/Maintainer gates apply |
| `validate` / `health` | L4 read-only | Read-only audit |
| `activate` | L3 | Runtime Owner confirmation |
| `mission *` | L3 | Mission Packet + Ledger writes |
