# 1.5.5 — Runtime Event Model

## Purpose

This contract defines the **canonical runtime event taxonomy** for Context OS.

Events are how lifecycles, components, and agents observe and react to each
other. Without an explicit event model, the Runtime is silently coupled and
unobservable.

Implementation is delegated to the Runtime event bus, introduced with later
orchestration and agent-runtime release slices.

---

## Principles

1. **Every meaningful state change emits an event.** Silent mutation is
   forbidden.
2. **Events are immutable.** Corrections are emitted as new events.
3. **Events are causally linked.** Every event carries `caused_by` when
   produced in response to another event.
4. **Events are typed.** A small, stable taxonomy is preferred over ad-hoc
   names.
5. **Events are append-only.** The event stream is a ledger.

---

## Common Envelope

```yaml
event:
  schema: contextos.event/1
  id: <ulid>
  type: <category>.<name>
  emitted_at: <iso8601>
  emitter: <component or agent id>
  caused_by: <event id or null>
  mission_id: <ulid or null>
  authority:
    role: <role or null>
    level: L0..L5 or null
  payload: <type-specific object>
  evidence_refs: [<artifact path or graph selector>...]
```

## Event Categories

### `runtime.*`
Runtime lifecycle and infrastructure events.

| Name | Emitted when |
|---|---|
| `runtime.installed` | Installation completed |
| `runtime.activated` | Bootstrap Step 9 succeeded |
| `runtime.upgraded` | Runtime version transitioned |
| `runtime.retired` | Runtime instance decommissioned |
| `runtime.health.reported` | Periodic Context Health Report produced |

### `readiness.*`
Context Readiness Assessment events
(see [`1.5.6 Context Readiness Assessment Contract`](1.5.6_Context_Readiness_Assessment_Contract.md)).

| Name | Emitted when |
|---|---|
| `readiness.assessed` | Context Readiness Assessment report produced |

### `discovery.*`
Discovery Engine activity.

| Name | Emitted when |
|---|---|
| `discovery.source.registered` | Source added to Connector Manifest |
| `discovery.scan.started` | Scan invoked |
| `discovery.scan.completed` | Scan produced a bundle |
| `discovery.conflict.detected` | Discovered fact conflicts with SSOT |

### `knowledge.*`
Knowledge Engine activity.

| Name | Emitted when |
|---|---|
| `knowledge.ingested` | Document added to Raw Knowledge Index |
| `knowledge.interpreted` | Interpretation pass produced drafts |

### `builder.*`
Context Builder activity.

| Name | Emitted when |
|---|---|
| `builder.mom.proposed` | MOM drafts produced |
| `builder.ssot.promoted` | Drafts committed into SSOT |

### `graph.*`
Context Graph events
(see [`1.5.3 Context Graph Schema`](1.5.3_Context_Graph_Schema.md)).

| Name | Emitted when |
|---|---|
| `graph.built` | Initial graph build complete |
| `graph.validated` | Graph passed integrity checks |
| `graph.published` | Graph version made queryable |
| `graph.rederived` | Derivation rule version changed |
| `graph.evolved` | Incremental update applied |

### `validation.*`
Validation Layer events
(see [`1.5.1 Validator Contract`](1.5.1_Validator_Contract.md)).

| Name | Emitted when |
|---|---|
| `validation.run` | Validator invoked |
| `validation.passed` | Run completed with no blocking findings |
| `validation.blocked` | Run completed with `error` findings |
| `validation.fatal` | Validator could not complete |
| `drift.detected` | Drift category produced findings |

### `mission.*`
Mission Lifecycle events
(see [`1.5.4 Mission Contract`](1.5.4_Mission_Contract.md)).

| Name | Emitted when |
|---|---|
| `mission.drafted` | Packet created in `draft` |
| `mission.proposed` | Packet submitted |
| `mission.accepted` | Owner accepted |
| `mission.planned` | Decomposition complete |
| `mission.executing` | Execution started |
| `mission.verifying` | Verification started |
| `mission.integrating` | Integration started |
| `mission.closed` | Mission terminal |
| `mission.cancelled` | Mission terminal without delivery |
| `mission.escalated` | Mission paused for human resolution |

### `governance.*`
Governance Lifecycle and Authority events.

| Name | Emitted when |
|---|---|
| `governance.policy.updated` | Policy added or modified |
| `governance.roster.updated` | Governance roster changed |
| `governance.decision.recorded` | Decision Record produced |
| `governance.violation.detected` | Action exceeded authority bounds |
| `authority.granted` | Capability granted at level |
| `authority.revoked` | Capability revoked |
| `authority.promoted` | Capability autonomy level raised |
| `authority.demoted` | Capability autonomy level lowered |

### `activation.*`
Activation Layer events.

| Name | Emitted when |
|---|---|
| `activation.surface.online` | Surface (IDE/Copilot/etc.) attached |
| `activation.surface.offline` | Surface detached |
| `agent.activated` | Agent role instantiated |
| `agent.deactivated` | Agent role stopped |

### `context.*`
Context Evolution events.

| Name | Emitted when |
|---|---|
| `context.hypothesis.created` | Hypothesis recorded |
| `context.hypothesis.verified` | Promoted to `verified` |
| `context.hypothesis.killed` | Falsified |
| `context.artifact.updated` | SSOT artifact changed |
| `context.ownership.changed` | Owner field changed |

### `cli.*`
CLI invocations
(see [`1.5.2 CLI Contract`](1.5.2_CLI_Contract.md)).

| Name | Emitted when |
|---|---|
| `cli.run` | Any `contextos` command invoked |

## Causality and Ordering

- Events within a single mission are **causally ordered** by `caused_by`.
- The bus must preserve **per-emitter monotonic ordering**.
- Global ordering is not guaranteed; consumers must reconcile via
  `caused_by` and `mission_id`.

---

## Observability Hooks

Every event must be:

- Persisted to the Accountability Ledger when `authority.level >= L3` or
  category in `{governance.*, mission.*, validation.blocked, validation.fatal,
  authority.*}`.
- Queryable by `mission_id`, `type`, time range.
- Inspectable via `contextos mission show` and Health Report tooling.

---

## Anti-Patterns

- Coalescing multiple state changes into a single event.
- Emitting events without `caused_by` when one is available.
- Treating events as a notification bus only (events are the audit trail).
- Adding new event types without category alignment.

---

## Versioning

Event schema is `contextos.event/<n>`. Adding a new event type within an
existing category is non-breaking. Renaming, removing, or changing payload
shape is breaking and requires a Governance decision.
