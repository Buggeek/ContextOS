# Contributing to Context OS

Thank you for your interest in contributing to Context OS.

Context OS is a structural framework. 
Clarity and coherence are more important than speed.

---

## Guiding Principle

Structure before expansion.

All contributions must preserve:

- Architectural coherence
- Taxonomy integrity
- Governance consistency
- Traceability across layers

---

## What Can Be Contributed

You may propose:

- Template improvements
- Additional examples
- Clarifications to documentation
- Implementation guides
- Tooling adapters (future layers)
- Adoption case studies

---

## What Requires Architectural Discussion

The following changes require discussion before implementation:

- New document categories
- Changes to taxonomy structure
- Governance model modifications
- Core principle adjustments
- Architectural layer changes

Open an issue before submitting a PR for these.

---

## Contribution Process

1. Fork the repository
2. Create a feature branch
3. Make changes
4. Ensure cross-references remain valid
5. Submit Pull Request with explanation

---

## Style Rules

- Use clear markdown structure
- Follow naming conventions
- Maintain version headers in documents
- Avoid redundant document types
- Preserve traceability links

---

## Anti-Entropy Rule

No document should exist without mapping to taxonomy.

No structural mutation without rationale.

Clarity compounds. Entropy spreads.

Choose clarity.
